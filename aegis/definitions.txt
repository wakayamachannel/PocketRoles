# [tools]    a running process name with spaces, '-' and '_' removed: "name*" matches the start, "name" the whole name.
#            Memory editors, trainers, injectors, cheat menus — for any game, not only Among Us. Entries shorter than

# [dlls]     file names next to Among Us.exe that cheats load through (BepInEx's own winhttp.dll is never flagged)
# [dllwords] parts of a DLL file name next to Among Us.exe (4 letters or more)
# [rules]    (the mod, v0.5.5+) numbers and rule levels of the in-game Aegis, documented below. The tray app skips it.
# [ngwords] [ngallow] (the mod, v0.5.5+) NG words of the chat filter, documented at the end. The tray app skips them.

#          documented in the section.
#
# Hidden entries (v0.5.5): the code that reads this file is public (GPL), but the lists themselves are stored so they cannot
# be read off at a glance — as salted HMAC hashes, not plain words. A hidden entry is a comment line (the salt is one header
# line before the first section):
#   hashsalt=<hex>                     one line, before the first section (a public salt: it is not secret)

# Read by the PocketRoles mod (v0.5.5 or later), the Aegis tray app and the launcher: the minimum PocketRoles version.
# A host whose PocketRoles is older cannot create rooms with it: the mod refuses the Create button, the automatic
# re-host and the lobby re-creations (a room already open goes on) and shows a notice on the title screen and in
# /ac rules; the launcher's "Launch" offers only "Update" (and plain Among Us from Steam); the tray app shows it in its
# scan. Joining other people's rooms, the settings and Freeplay still work, and plain Among Us started from Steam is
# not touched at all (PocketRoles lives only in its separate copy, "Among Us PocketRoles"). Used whatever
# [AntiCheat] RemoteRules says; an offline host uses the newest verified file in its cache.
# v0.5.4 and older do not read this section, so it cannot stop them; nor a host who built or changed the mod (the
# source is GPL). Either way only that host's own rooms are affected.
#
# Format: minmod = <version> [@conditions], one per line ('#' starts a comment):
#   version     3 numbers, e.g. 0.5.6 (a build like 0.5.6-beta counts as older than 0.5.6)
#   conditions  as in [rules] (@mod / @game). The highest minmod whose conditions surely hold counts; a line whose
#               condition the mod cannot judge never counts. Several lines are fine, e.g. a general one and a higher
#               one for a new game version (minmod = 0.5.7 @game>=2026.9.1). Other keys are for later versions and
#               are ignored. At most 50 lines.
# Safety: the signing tool refuses a minmod above the version of this repository, and, when a minmod is raised, one
# above the newest PocketRoles release published on GitHub (it asks GitHub; offline it refuses to raise it). The mod
# ignores a minmod more than one major version ahead of its own (0.x ignores 2.0.0) or with a number above 999, as a
# typo. The floor never depends on the PC's clock or date: only version numbers are compared.
# Release day: publish the release on GitHub first, then write minmod here, raise version= at the top and sign.
# A mistake: lower or remove the line, raise version= and sign. Hosts pick it up at their next start; a blocked host's
# mod also asks GitHub again when the online menu opens or a room is refused (at most every 5 minutes).
# A leaked signing key: a mod release that revokes it (RevokedKeyIds) makes every host ignore files signed with it,
# a forged minmod too.
#
# Example (not active):
# minmod = 0.5.6

[rules]
# Read by the PocketRoles mod (v0.5.5 or later), not by the tray app. Fixes a false positive or a loophole of the
# in-game Aegis for every host without a mod release (a new kind of detection still needs a mod update). The mod
# fetches this file when the game starts and with /ac rules reload, keeps the last one it applied in
# BepInEx\PocketRoles\aegis-rules-cache.txt, and takes a fetched file only when its signature (definitions.txt.sig)
# checks out and its version= is newer than the file in use (over the built-in values: at least 2, the oldest the mod
# accepts). In every lobby the mod varies most values at random by up to [AntiCheat] Jitter percent (default 10;
# never outside a key's range; not repeat.count, callout.*, votecallout.lobby, speed.snap, speed.window,
# chatalive.grace; see /ac rules lobby). /ac rules shows the values in use; [AntiCheat] RemoteRules = false
# (/opt anticheat.remoterules off) keeps the built-in numbers, but level lines that end at notice or off (after the
# version conditions below) and the [update] section still apply there. Raise version= at the top when you change a
# line here.
#
# Format: key = value, one per line ('#' starts a comment, keys are case-insensitive, at most 200 lines). A key that is
# not written keeps its built-in value. A value outside its range is clamped into it; unknown keys and bad values are
# ignored (both are written to the BepInEx log).
#
# key                  built-in  range       meaning
# chatflood.count      5         3..20       ChatFlood: this many chat lines (typed or quick chat) ...
# chatflood.window     3         1..10       ... within this many seconds
# color.lobby.count    20        8..60       ColorSpam in the lobby: this many colour changes ...
# color.lobby.window   3         1..10       ... within this many seconds
# speed.kick           2.5       1.6..6      SpeedHack: moving faster than this x the player's speed setting
# speed.notice         1.8       1.3..6      SpeedFast: faster than this x (never above speed.kick)
# speed.window         2         1..5        seconds of movement averaged for both speed rules
# speed.snap           1.2       0.5..3      a single-frame step longer than this (units) is a jump, not walking
# vent.base            1.5       0.5..5      VentFar: farther from the vent than vent.base + max(2.5, speed) x vent.factor
# vent.factor          0.8       0.3..3
# repeat.count         2         2..5        Repeat rules: removed at this many separate episodes ...
# repeat.gap           10        3..120      ... at least this many seconds apart ...
# repeat.window        300       30..3600    ... each within this many seconds of the previous one
# killcd.ratio         0.5       0.1..0.9    KillCooldown: a kill sooner than cooldown x killcd.ratio - killcd.margin (s)
# killcd.margin        2         0..10
# killdist.factor      2         1..5        KillDistance: farther than kill distance x killdist.factor + killdist.add
# killdist.add         3         0..10
# taskburst.count      4         3..10       TaskBurst: this many task completions ...
# taskburst.window     2         0.5..10     ... within this many seconds
# chatalive.grace      8         3..30       ChatAlive: chat this many seconds after a meeting / exile / intro is not counted
# callout.game         2         2..6        Callout: hidden impostors named in one game (with no wrong name)
# callout.lobby        3         3..10       CalloutRepeat: hidden impostors named over the games of one lobby
# votecallout.lobby    3         3..10       VoteCallout: votes for hidden impostors in meetings with no clue yet (no
#                                            impostor action, no impostor dead), from 2+ games of one lobby
# (whole numbers only: chatflood.count, color.lobby.count, repeat.count, taskburst.count, callout.game, callout.lobby,
#  votecallout.lobby)
#
# level.<rule> = off | notice | repeat | certain      (<rule> = the rule name in the log, e.g. level.SpeedFast = off)
#   certain = removed at the first hit, repeat = removed at repeat.count episodes, notice = the host's screen only,
#   off = the log line only (no notice, no count in /ac, no removal).
#   A file may only make a rule's LEVEL more lenient than built in (off < notice < repeat < certain); a stricter
#   value is ignored, so this file can never turn a notice rule into a removal. The numbers above can move either
#   way (stricter too, to close a loophole), but only within their range.
#   Built in: certain = KillRole VentRole AbilityRole TaskImpostor
#             repeat  = ChatAlive ChatFlood SpeedHack
#             notice  = KillDead SabotageCrew KillCooldown ProtectAlive TaskUnknown KillDistance RpcUnknown TaskBurst
#                       ReportForge Teleport KillPhase Callout CalloutRepeat NameChange ColorSpam SpeedFast VentFar
#                       VoteCallout
#
# Version-scoped lines (read from v0.5.5 on): a line may end with "@" and conditions on the PocketRoles version (mod)
# and the Among Us version (game), separated by commas (all of them must hold):
#   level.KillRole = notice      @mod<=0.5.5                  # only 0.5.5 and older; the fixed version and newer keep the built-in level
#   speed.kick = 3               @mod>=0.5.6, game>=2026.9.1
#   level.SpeedFast = off                                      # everyone
#   level.SpeedFast = notice     @mod>=0.5.7                   # back to built-in from 0.5.7 (the last line that applies wins)
#   Operators: <= >= == = < >. Write versions with 3 numbers (0.5.5; the signing tool refuses a condition it cannot
#   read: "mod<=0.5" would mean 0.5.0 or older). A build like 0.5.6-beta counts as older than 0.5.6.
#   The lines are read top to bottom and the last line that applies wins: write the general line first and the scoped
#   ones after it. A condition the mod cannot judge (an unknown word, a typo, or the game version not known yet right
#   after the start) only ever makes a rule more lenient: such a line is used only where it relaxes the value it would
#   replace. A level still never goes above the built-in one. With RemoteRules = false only the level lines that end at
#   notice or off are used (the numbers stay built in). v0.5.4 and older do not read [rules] at all.
#
# Example lines (none is active; remove the leading "# " to use one):
# speed.kick = 3
# level.SpeedFast = off
# level.KillRole = notice @mod<=0.5.5

# when this file's signature checks out (like [rules]) and [AntiCheat] SharedBans is on (default). A listed player who
# joins is told first (in a registered lobby privately, in an unregistered one by a public line without a name; both

# cannot be guessed back; a friend code is a word and 4 digits, so a hash of it could be (the console app lists PUID

#            the length of the shared ban: only expires does. The console app shows it and suggests an expiry from it
#            (1: 30 days, 2: 180 days, 3: never). While the line has not expired (and [AntiCheat] SharedBans is on), the
#            mod counts it as the player's earlier offences when this host bans them: a ban on the ladder ([AntiCheat]
#            BanLadder) goes on from it (after level 1: 180 days, after 2 or more: permanent)
#   expires  yyyy-mm-dd (UTC; the ban applies through the end of that day) or never
#   reason   a short code of a-z 0-9 _ . - (e.g. killrole, speedhack, cheat, chat, harass, name, manual)

# that player up to that day go too (a line still here keeps the player banned, whatever [unban] says). Remove the

# reason to the code. Raise version= at the top and sign the file after every change.

[erase]
# Read by the PocketRoles mod (v0.5.5 or later), not by the tray app: the erase list. A player types /cmd id in a
# PocketRoles room, gets a code (16 letters, e.g. BDZN XHNJ JSXD GZDG) and sends it to the author, who lists it here
# with a date. Every verified file (signature and version checked as above) is used for this list, also with
# [AntiCheat] RemoteRules = false: the mod then fetches the file for this list alone (when the game starts and once a
# day while it runs). Each host's PC then erases that player's records up to the date + 2 days: the name, history and
# other details in aegis-bans.json, and the evidence records (those younger than 30 days lose the name, the room code,
# the detection text and the log lines; the rest, such as the hashes and the detection numbers, stays until their 30
# days are up). It keeps what a ban still in force needs (and that ban's evidence, for appeals), the minimum of the
# offence count (a year after the last ban), the host's own lists (Banlist.txt, VIP.txt, ...) and the logs (deleted
# after 30 days anyway).
# This file is public: list ONLY codes and dates. No names, no friend codes, no notes (not even after a '#' on a code
# line: the mod ignores that text, but it is published with the file).
#
# Format: one request per line, fields separated by spaces or tabs ('#' at the start of a line is a comment):
#   <code> <yyyy-mm-dd>   the code as /cmd id shows it (4 groups of 4 with spaces), or with '-' or nothing between the
#                         groups, then the date
#   @<yyyy-mm-dd>         a date line: every bare <code> line below it (up to the next @ line) takes this date
#   code   16 letters of BDFGHJKMNPRSTVXZ (full-width letters also work). The last one is a check letter: a typo in
#          one letter is caught 15 times in 16 and the line is rejected (only the count goes to the host's log).
#   date   the day the request arrived (read as UTC), never a later day: a date more than 3 days ahead of a host's
#          clock is rejected. Records after the date (+2 days) are not erased; they go by the 30-day deletion.
# Keep a request listed for at least 90 days, so that hosts that have not started PocketRoles for a while still get it
# (by then the 90-day deletion of evidence records (logs still go at 30 days) has removed most of the same anyway).
# Not the evidence of a ban still in force: that is kept while the ban lasts, and when the ban ends a request still
# listed erases it at once (as above), else it goes 30 days later. So for a player whose ban you know was in force on
# the request date (a shared ban, a ban in your own rooms), keep the request until that ban has ended. Then it may go.
# A code listed twice keeps the later date.
# The mod uses the newest 1000 requests. Keep [erase] under 16 KB: the whole file must stay under 64 KB, or every
# host refuses all of it (rules, NG words and shared bans too). Raise version= at the top and sign the file after
# every change.
#
# Example (not active): a date line with a bare code under it, or a code with its own date:
# @2026-09-22
# BDZN XHNJ JSXD GZDG

[ngwords]
# Read by the PocketRoles mod (v0.5.5 or later), not by the tray app: the NG words of the chat filter (/ng). When this
# section exists it replaces the mod's built-in list (so a word deleted here is gone for every host), and [ngallow]
# replaces the built-in allow list. The host's own BepInEx\PocketRoles\NgWords.txt is added on top of both.
# Lines are matched against the normalized message (NFKC, lower case, katakana -> hiragana, a wave dash right after
# kana -> the long-vowel mark); a separator is any character that is not a letter or digit (the long-vowel mark counts
# as a letter). One entry per line, '#' comments:
#   word     anywhere in the message with every separator removed (so it also catches the letters split by spaces)
#   <word    starts at the start of the message or right after a separator (matched with the separators kept)
#   word>    ends at the end of the message or right before a separator (matched with the separators kept)
#   <word>   a whole token (both)
# From v0.5.5 (2026-09-22), for entries that are not pure ASCII (pure-ASCII ones keep the rules above). The examples
# below use an INVENTED word ほげら (hogera): no real entry is written in this file any more (they are all hashed):
#   - romaji: the message is also read as romaji and matched again ("hogera" "hoge ra" "h o g e r a" = ほげら).
#     ASCII that does not read wholly as romaji stays as it is (shiny, sky, the), and the allow list works on the
#     reading too (hogeramu = ほげらむ), also across the spaces between romaji words when the phrase runs on past the
#     NG word ("ore ga hogeraba" = がほげらば), and an ASCII allow phrase covers the reading of its letters. In the
#     reading, a hit spread over several words must begin and end a word ("hoge ra" hits, "ichiman koete" does not).
#   - spaced out: <word / word> also match with separators inside the word when its first letter starts the message or
#     follows a separator and its last letter ends the message or comes before one ("ほ げら" hits; "よほ げらよう"
#     does not).
#   - a player's name written at the start of the message or after a separator counts as a separator before <word
#     ("もりほげら" hits <ほげら when a player named もり is in the room).
# An entry needs 2 letters after normalization, a pure-ASCII one 3 unless written as <word>; at most 1000 per section.
# [ngallow]: phrases blanked out of the message before matching (they protect ordinary words that contain an NG string).
# A blanked phrase also hides an NG word it overlaps, so never let an allow phrase start or end inside a common form of
# an NG word (with the invented ほげら: write まえほげら, not えほげら, which would hide おまえほげら). A hit lying
# wholly inside the name of another player in the room does not count either (the mod does that, not this file).
