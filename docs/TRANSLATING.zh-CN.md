# 翻译方法

[日本語](TRANSLATING.md) | [English](TRANSLATING.en.md) | [简体中文](TRANSLATING.zh-CN.md)

PocketRoles 在游戏里显示的文字，放在 3 个语言文件里。
本页是给修改翻译的人的规则。怎样提交 Pull Request，请看 [CONTRIBUTING.zh-CN.md](../CONTRIBUTING.zh-CN.md)。

## 文件

| 文件 | 语言 |
|---|---|
| `lang/ja.json` | 日语（原文。另外两个文件以它为准） |
| `lang/zh-CN.json` | 简体中文 |
| `lang/en.json` | 英语 |

- 编码是 **UTF-8（无 BOM）**。用 Windows 的记事本时，保存时选“UTF-8”（不是“带有 BOM 的 UTF-8”）。也推荐使用 VS Code 等编辑器。
- 可以直接修改 GitHub 上现在的版本（`main`）。即使作者手里有还没发布的新版本也没关系：采用时，作者会把你改过的地方一条一条地（按键）也放进新版本。

## 文件格式

每一行是一个 `"键": "文字"`。

```json
{
  "cmd.lang.set": "语言已设为 {0}。",
  "role.sheriff.name": "警长",
  "kill.bite": "你咬了 {0}，对方将在 {1:0.#} 秒后死亡。"
}
```

- 不要改 **键**（左边的 `"cmd.lang.set"`），也不要删除或添加键。3 个文件有同样的键。
- 只改 **文字**（右边）。想知道一个键是什么意思，对照 3 个文件里的同一个键就能明白。
- 文字里的 `"` 要写成 `\"`，`\` 要写成 `\\`。换行写成 `\n`（不要真的换行）。
- 最后一行后面不加 `,`。不能写注释（`//`）。
- 不要改变行的顺序（这样方便和其他语言的文件对照）。

## 要原样保留的东西

### 占位符 `{0}` `{1}`

- `{0}`、`{1:0.#}` 这样的 `{ }` 里会放进名字、数字、职业名等。**请原样保留**，里面的数字和 `:0.#` 也不要改。
- 可以按照语言的语序，在句子里移动它的位置。例：`"{0} に噛みつきました。"` → `"你咬了 {0}。"`
- 使用半角的 `{ }`。全角的 `｛ ｝` 不行。
- `{rules}` 这样带英文名字的 `{ }` 是命令说明的一部分，也要原样保留。

### 标签 `< >`

- 如果文字里有 `<color=#ff0000>…</color>` 这样的颜色标签，请同样保留（现在的文件里没有，颜色由模组自己加）。
- `<名字>`、`<职业>` 这样的 `< >` 是命令写法的说明，里面的词可以翻译。
- 但是不要在 `< >` 里写游戏会当作“格式”来读的词，例如 `<b>` `<i>` `<u>` `<s>` `<size>`。
  例如英语把秒写成 `<s>`，游戏会把后面的文字都加上删除线（要写成 `<seconds>`）。

### 换行 `\n`

- `\n` 的数量要和日语原文相同。每一行都会成为单独的聊天行。

### 开头的空格或逗号

- 以空格或逗号开头的文字（例如 `" 击杀CD{0:0.#}秒"`）会接在别的文字后面使用。不要删掉开头的空格或逗号（按照语言把日语的空格改成英语的 `, ` 这样的修改没关系）。

## 聊天长度

模组的大部分文字都通过游戏聊天发送。一条聊天消息能放的字数是有限的。

| 房间 | 一条消息能放的字数 |
|---|---|
| 注册房间（模组职业房） | 100 个字符 |
| 未注册房间（简易房） | 86 个字符（因为开头会加上“[PocketRoles] ”） |

- 按字符数计算。汉字、假名、字母、数字、空格都算 1 个字符。`{0}` 里会放进名字等，按 10 个字符左右计算。
- 太长的文字，模组会自动分成几条发送。但是条数多了就不好读。
  一行（两个 `\n` 之间）超过 100 个字符时，会在中间断开，接到下一条。
- 下面这些文字 **规定必须放进一条消息**（放不下时检查会报错）：
  - 未注册房间的欢迎语 `compat.welcome`（86 个字符）
  - 违禁词的警告 `ng.warn`、`ng.warn.left`、`ng.warn.only`（放进 10 个字符的名字后 86 个字符）
  - 其他（限制进入的通知等）。完整列表在 `tools/check-lang.ps1` 的开头部分。
- `/h` 帮助和进入房间时的欢迎语（`welcome.*`）有条数上限。超过的部分会被“…”截断。
- 在未注册房间里显示的文字（`compat.*`、`help.compat.*`、`about.compat.*` 等）中，游戏聊天里打不出来的字符会被删掉。
  会留下的是：文字、数字和 `? ! , . ' : ; ( ) / \ % ^ & - = #`，以及 `。` `、` `・` `ー` `「」` `『』` `【】`（全角的 `！（）：` 等会变成半角后留下）。
  `→` `★` `♪` 和表情符号会被删掉。`< >` 这两个符号也会被删掉。
  - `<` 后面紧接着以 b、i、u、s 等开头的词（`<seconds>`、`<id>`、`<user>` 等），在未注册房间里会连同里面的词一起被删掉。这类文字请换成 `<time>` 这样的别的词。
  - “…”会变成“...”（3 个字符）。规定必须放进一条消息的文字，按“...”计算（检查也这样计算）。

### 确认长度

- 提交 Pull Request 后，自动检查（pr-checks）会计算长度。对每一条改过的文字，会在检查的 Summary 里显示“之前的条数 → 现在的条数”和“最长一行的字符数”。
- 屏幕上数字的说明是英语：`messages` = 条数，`longest line` = 最长一行的字符数，`keys` = 键的数量，`chat texts` = 聊天文字的数量，`changed` = 改过的文字。文件检查（check-files）的理由也是英语。
- 想在自己的电脑上确认时，在仓库文件夹里输入下面的命令（PowerShell 7 用 `pwsh tools/check-lang.ps1`）。
  加上 `-BaseRef origin/main`，就只显示从 `main` 以来改过的文字的之前和现在。

  ```
  powershell -NoProfile -ExecutionPolicy Bypass -File tools\check-lang.ps1 -BaseRef origin/main
  ```

  `origin/main` 是你的 Fork 的 `main`。把原仓库添加为 `upstream` 的人，请用 `-BaseRef upstream/main`
  （添加方法：`git remote add upstream https://github.com/wakayamachannel/PocketRoles.git`，然后 `git fetch upstream`）。

- `ERROR` 必须修改。`WARN` 由作者和你一起确认。

## 使用游戏的官方用语

- 游戏里有的词（伪装者、船员、通风口、任务、破坏、会议、游戏里的职业名等），要和游戏在该语言里的 **官方翻译** 一致。
  - 例（中文）：Impostor 是“伪装者”（不是“内鬼”），Crewmate 是“船员”。
- 仓库里还没有官方用语的列表（作者正在决定要不要放进来）。在那之前，请和上面的例子以及现在 `zh-CN.json` 里的译法保持一致。作者在采用时，也会在自己的电脑上和官方用语对照。
- 只有模组才有的词（警长、豺狼等模组职业的名字），和现在文件里的译法保持一致。
  职业名也会在命令里使用（例如 `/cmd r 名字`），所以想改的时候请在 Pull Request 里写明理由。作者会连同代码一起确认。

## 在游戏里试一试

可以按照 [README 的“文本文件（可编辑）”](../README.zh-CN.md#文本文件可编辑)，在房主的电脑上试。

1. 在装了模组的游戏副本（`Among Us PocketRoles`）的 `BepInEx\PocketRoles\lang\` 里，用你改好的文件替换同名的文件（先把原来的文件复制到别的地方）。
2. 在房间里，房主输入 `/lang reload`，或者重新启动游戏。
3. 房主输入 `/lang zh`（中文）或 `/lang en`（英语）后，给房主显示的文字和房间的语言会切换过去。用 `/h` 等查看文字。
   只发给玩家的文字，可以用手机等作为第二个人进入房间来查看。
4. 试完后，房主输入 `/lang ja`，把房间的语言改回来（用 `/lang zh` 或 `/lang en` 改的房间语言会保存在设置里，下次也会保留）。
   把替换的文件换回事先复制的原文件，或者删除它（删除后，下次启动时模组会重新写出内置的文字）。
   如果不这样做，这台电脑会一直使用你测试用的文字。
