# 角色（谁可以做什么）

[日本語](ROLES.md) | [English](ROLES.en.md) | [简体中文](ROLES.zh-CN.md)

这是制作和帮助 PocketRoles 的人的角色。帮忙的人越来越多了，所以本页整理了谁可以做什么，以及怎样请人担任角色。
除了这里写的内容，每个人都要遵守[行为准则](../CODE_OF_CONDUCT.md#简体中文)。

## 一览

| 角色 | 谁 | 可以做的事 | 不做的事 |
|---|---|---|---|
| 贡献者 | 任何人 | Issue、Pull Request、评论 | 直接写入仓库 |
| 翻译负责人 | 经常帮忙某一种语言的人 | 阅读该语言的 Pull Request 并提出意见 | 采用（合并） |
| 管理员（Aegis 团队） | 所有者选出的人 | 用管理员模式使用 Aegis BAN 管理、提议限制进入 | 签名、更改全体限制进入、持有密钥 |
| 所有者（作者） | [@wakayamachannel](https://github.com/wakayamachannel) | 采用、发布、签名、持有密钥和秘密、决定角色 | — |

除了所有者，我们不给任何人 GitHub 仓库的写入权限（write）。任何角色的人都从自己的 Fork 提交 Pull Request。

## 贡献者（任何人）

- 写 Issue、提交 Pull Request、在 Pull Request 里评论。
- 提交方法和规则写在 [CONTRIBUTING.zh-CN.md](../CONTRIBUTING.zh-CN.md) 里。

## 翻译负责人

- 贡献者中，经常帮忙某一种语言（例如中文）翻译的人。
- 阅读该语言的 Pull Request，在评论里提出意见（“这样译更自然”“这不是游戏的官方用语”等）。所有者参考这些意见，决定是否采用。
- 在 CHANGELOG 的致谢中，连同负责的语言写上名字（不想写的话就不写。是否也写进 README，还没有决定）。
- 没有特别的权限。

## 管理员（Aegis 团队）

- 新版本（v0.5.5）完成后，所有者会选出信任的人，在 Discord 上直接交给他们“管理员工具包”。只使用从所有者那里直接拿到的工具包。
  - 确认是不是真的：所有者会在管理员频道置顶工具包 zip 的 SHA-256（像指纹一样的一长串字符）。
    打开之前，在 PowerShell 里输入 `Get-FileHash <zip 文件>`，看显示的字符是否和置顶的一样（不区分大小写）。不一样的话，不要打开，并告诉所有者。
  - 也可以确认里面的 `aegis\AegisBan.ps1` 和官方仓库（wakayamachannel/PocketRoles）同一版本的 `aegis/AegisBan.ps1` 是否相同。
- 可以做的事：
  - 用“管理员模式（仅提议）”使用 Aegis BAN 管理（在所有者以外的电脑上总是这个模式）
  - 查看自己房间的限制进入和证据、解除限制进入、更改期限
  - 导入其他房主的报告 zip
  - 写“加入”或“解除”全体限制进入（共享限制进入）的提议文，发到 Discord 的工单里
- 以后可能也会请管理员帮忙做支持工作（回答问题等；计划中）。
- 不做的事：更改全体限制进入（签名、发布到 GitHub）。管理员**绝不会**给 Aegis 定义文件签名。不持有密钥、密码、令牌，所有者也不会向管理员要这些东西。自称“所有者让我来的”并索要密钥或密码的人是冒充者。
- 要遵守的事：
  - 报告 zip 不贴到工单里，直接发到作者的邮箱（`pocketroles.report+host@gmail.com`），因为里面也有其他人的记录。
  - 好友编号只在申诉的工单里使用，不拿到其他地方。
  - 不把工具包交给别人（为了不让假的或旧的版本流传出去；工具包里没有秘密）。
- 为了防止骚扰，不在 GitHub 和 README 上公开管理员的名字。在 Discord 上也不给管理员能看出是管理员的身份组（见下面的“怎样请人担任角色”）。

## 所有者（作者）

- [@wakayamachannel](https://github.com/wakayamachannel)。GitHub 仓库、官方 Discord 和支持邮箱的所有者。
- 阅读 Pull Request，决定是否采用。只有所有者能把修改合并到 `main`（检查、构建、合并的操作会用到工具，但由所有者决定）。
- 发布新版本。给 Aegis 定义文件（`aegis/definitions.txt`）签名。决定全体限制进入。
- 持有密钥和秘密：定义文件的签名密钥、支持邮箱的密码、DeepL 的密钥、Discord 的 Webhook，以及今后开始的代码签名（SignPath）的批准。这些都不放进仓库，也不交给任何人。
- 在 GitHub 上使用双重身份验证（2FA），SignPath 账户也会使用（[代码签名政策](CODE-SIGNING.zh-CN.md)）。

## 怎样请人担任角色

1. 一开始，大家都是贡献者。
2. 提交过几次 Pull Request 或帮过忙、遵守行为准则、并且所有者在 Discord 等地方认识的人，所有者会请他担任“翻译负责人”或“管理员”。自己说“想做”也可以。
3. 请人担任管理员时，会先和所有者谈一谈，并请他阅读本页和管理员工具包的使用说明。
4. 翻译负责人会用 Discord 的身份组来表示。管理员不设其他人能看到的身份组，所有者会一个一个地把管理员加进管理员频道（因为 Discord 服务器里的任何人都能看到成员的身份组）。

## 取消角色的时候

- 以下情况，所有者会取消角色：
  - 没有遵守行为准则
  - 把好友编号、记录或报告 zip 泄露到外面
  - 索要密钥或密码，或者想把它们交出去
  - 把管理员工具包交给了别人
  - 很长时间联系不上
  - 本人说想退出
- 取消时，会移除 Discord 的身份组（翻译负责人）或管理员频道。
  曾经是管理员的人，除了管理员工具包及其所有副本，还要删除为了导入而收到的报告 zip，以及 Aegis BAN 管理的记录（`%LOCALAPPDATA%\PocketRoles\Aegis\ban-console`），因为里面有其他人的记录（位置和删除方法见[卸载方法的“只限管理员（Aegis 团队）”](UNINSTALL.zh-CN.md#6-只限管理员aegis-团队)）。
  之后的提议不再接受。
- 管理员没有拿到密钥，所以不需要重新生成密钥。如果发现秘密（密钥或 Webhook）泄露了，所有者会重新生成。
- 紧急时（角色被用来做坏事时），会先取消角色，之后再说明理由。
