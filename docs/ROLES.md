# 役割（だれが何をできるか）

[日本語](ROLES.md) | [English](ROLES.en.md) | [简体中文](ROLES.zh-CN.md)

PocketRoles を作る人・手伝う人の役割です。手伝ってくれる人が増えてきたので、だれが何をできるか、どうやって役割をお願いするかをまとめました。
ここに書いたことと別に、みんな[行動規範](../CODE_OF_CONDUCT.md)を守ります。

## 一覧

| 役割 | だれ | できること | しないこと |
|---|---|---|---|
| コントリビューター | だれでも | Issue、Pull Request、コメント | リポジトリに直接書きこむ |
| 翻訳の担当 | 1 つの言葉をよく手伝ってくれる人 | その言葉の Pull Request を読んで意見を言う | 取り込む（マージする） |
| 管理人（Aegis チーム） | 持ち主が選んだ人 | Aegis BAN 管理を管理人モードで使う・BAN の提案 | 署名・全体の BAN を変える・鍵を持つ |
| 持ち主（作者） | [@wakayamachannel](https://github.com/wakayamachannel) | 取り込む・リリース・署名・鍵と秘密を持つ・役割を決める | — |

GitHub のリポジトリに書きこむ権利（write）は、持ち主のほかにはだれにも渡しません。どの役割の人も、自分のフォークから Pull Request を出します。

## コントリビューター（だれでも）

- Issue を書く、Pull Request を出す、Pull Request にコメントする。
- 出し方と決まりは [CONTRIBUTING.md](../CONTRIBUTING.md) にあります。

## 翻訳の担当

- コントリビューターのうち、1 つの言葉（たとえば中文）の翻訳をよく手伝ってくれる人です。
- その言葉の Pull Request を読んで、コメントで意見を言います（「こちらの訳のほうが自然」「ゲームの公式の言葉とちがう」など）。持ち主はその意見を見て、取り込むかを決めます。
- CHANGELOG のお礼に、担当の言葉といっしょに名前をのせます（のせたくない時はのせません。README にものせるかは、これから決めます）。
- 特別な権利はありません。

## 管理人（Aegis チーム）

- 新しい版（v0.5.5）ができてから、持ち主が信頼できる人を選んで、Discord で直接「管理人キット」を渡します。キットは、持ち主から直接もらったものだけを使います。
  - 本物か確かめる: 持ち主は、管理人のチャンネルにキットの zip の SHA-256（指紋のような長い文字）をピン留めします。
    開く前に PowerShell で `Get-FileHash <zip のファイル>` と打ち、出た文字がピン留めと同じか見ます（大文字・小文字のちがいは気にしません）。ちがったら開かずに、持ち主に知らせます。
  - 中の `aegis\AegisBan.ps1` が、公式のリポジトリ（wakayamachannel/PocketRoles）のその版の `aegis/AegisBan.ps1` と同じかでも確かめられます。
- できること:
  - Aegis BAN 管理を「管理人モード（提案だけ）」で使う（持ち主の PC 以外では、いつもこのモードです）
  - 自分の部屋の BAN と証拠を見る・解除する・期間を変える
  - ほかのホストの報告 zip を取り込む
  - 全体の BAN（共有 BAN）に「載せる」「解除する」の提案文を作って、Discord のチケットに出す
- あとで、サポートのお手伝い（質問への返事など）もお願いするかもしれません（予定です）。
- しないこと: 全体の BAN を変えること（署名・GitHub への反映）。Aegis の定義ファイルに署名することは**ありません**。鍵・パスワード・トークンは持ちません。持ち主が、それを頼むこともありません。「持ち主から」と言って鍵やパスワードを求めてくる人は偽物です。
- 守ること:
  - 報告 zip はチケットに貼らず、作者のメール（`pocketroles.report+host@gmail.com`）に直接送ります（ほかの人の記録も入っているため）。
  - フレンドコードは、異議申し立てのチケットの中だけで使い、ほかには出しません。
  - キットをほかの人に渡しません（偽物や古い版が出回らないようにするためです。キットに秘密は入っていません）。
- 管理人の名前は、いやがらせを防ぐため、GitHub や README では公開しません。Discord でも、管理人と分かる役職は付けません（下の「役割のお願いのしかた」）。

## 持ち主（作者）

- [@wakayamachannel](https://github.com/wakayamachannel)。GitHub のリポジトリ・公式 Discord・サポートのメールの持ち主です。
- Pull Request を読んで、取り込むかどうかを決めます。`main` に取り込めるのは持ち主だけです（チェック・ビルド・取り込みの作業には道具を使いますが、決めるのは持ち主です）。
- リリースを出す。Aegis の定義ファイル（`aegis/definitions.txt`）に署名する。全体の BAN を決める。
- 鍵と秘密を持つ: 定義ファイルの署名の鍵、サポートのメールのパスワード、DeepL のキー、Discord のウェブフック、これから始めるコード署名（SignPath）の承認。どれもリポジトリには入れず、だれにも渡しません。
- GitHub では 2 段階認証を使います。SignPath のアカウントでも使います（[コード署名のポリシー](CODE-SIGNING.md)）。

## 役割のお願いのしかた

1. はじめは、みんなコントリビューターです。
2. 何回か Pull Request や手伝いをしてくれて、行動規範を守っていて、持ち主が Discord などで知っている人に、持ち主から「翻訳の担当」や「管理人」をお願いします。「やりたい」と自分から言ってもらってもかまいません。
3. 管理人をお願いする時は、先に持ち主と話をして、このページと管理人キットの使い方を読んでもらいます。
4. 翻訳の担当は、Discord の役職で分かるようにします。管理人には、ほかの人から見える役職は付けず、管理人のチャンネルに入れる人を 1 人ずつ決めます（Discord の役職は、サーバーのだれでも見られるため）。

## 役割を外す時

- 次の時は、持ち主が役割を外します。
  - 行動規範を守らなかった
  - フレンドコード・記録・報告 zip を外に出した
  - 鍵やパスワードを求めた、または渡そうとした
  - 管理人キットをほかの人に渡した
  - 長い間、連絡が取れない
  - 本人がやめたいと言った
- 外す時は、Discord の役職（翻訳の担当）や管理人のチャンネルから外します。
  管理人だった人には、管理人キットとそのコピーに加えて、取り込むためにもらった報告 zip と、Aegis BAN 管理の記録（`%LOCALAPPDATA%\PocketRoles\Aegis\ban-console`）も消してもらいます。ほかの人の記録が入っているためです（場所と消し方は、[消し方の「管理人（Aegis チーム）の人だけ」](UNINSTALL.md#6-管理人aegis-チームの人だけ)）。
  それからあとの提案は受け取りません。
- 管理人には鍵を渡していないので、鍵を作り直す必要はありません。もし秘密（キーやウェブフック）が漏れたと分かった時は、持ち主がそれを作り直します。
- 急ぐ時（悪いことに使われている時）は、先に外して、あとで理由を伝えます。
