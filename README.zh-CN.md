**这是一个只需建房的人安装的 Among Us（2026.8.18 / Steam）职业模组。** 朋友们用 PC、手机或 Switch 上平时的 Among Us，输入房间代码就能加入。警长、豺狼、小丑等 26 种职业会通过名字标签和聊天悄悄地只告诉本人。设置在房间的电脑里完成，提示支持 日本語 / 中文 / English 三种语言，外语聊天自动翻译，房间超时和拖沓的会议也能由房主一键处理。免费、非营利，源代码在 GitHub 公开（**v0.5.0**，旧名 HostRoles）。

- **玩家什么都不用装** — 模组只装在房主的一台 PC 上。其他人保持原版，像平时一样玩
- **26 种职业，三种语言悄悄告知** — 警长、市长、告密者、豺狼、小丑、恋人……职业说明以 日本語 / 中文 / English 只发给本人，外语聊天自动翻译（并用模式）
- **让房主轻松的工具** — 房间剩余时间常驻显示并自动延长、自动开始、废村（F7）、强制结束会议（F8）、取消开始（F9）、房间代码大字显示（`/code` 开启，默认关闭）、给朋友用的安装器

## 3 分钟安装（Windows + Steam 版）

1. 从 **[GitHub Releases](https://github.com/wakayamachannel/PocketRoles/releases)** 下载两个 zip：`PocketRoles-Setup-0.5.0.zip`（启动器）和 `PocketRoles-0.5.0.zip`（模组本体）。
2. **把两个 zip 解压到同一个文件夹**（例如 `文档\PocketRoles`，放在不会删除的地方。有网络时只用 Setup zip 也可以 — 启动器会自动下载本体）。
3. **双击“PocketRoles Launcher.cmd”**。出现蓝色的“Windows 已保护你的电脑”时，点“更多信息”→“仍要运行”（这是因为没有使用代码签名证书，不是病毒）。
4. 点击 **“安装”**。启动器会把 Steam 版 Among Us 复制到桌面的“Among Us PocketRoles”，并自动安装 BepInEx 和 PocketRoles（需要几分钟。Steam 版本身不会被修改）。如果桌面由 OneDrive 备份，则改为复制到 `%LOCALAPPDATA%\PocketRoles\Among Us PocketRoles`（避免把 1 GB 同步到云端；启动器参数 `-GameDir` 可以选择任意文件夹）。
5. **先启动 Steam，再点“启动”**。首次启动到标题画面需要 1〜2 分钟（中途出现黑色窗口也请不要关闭）。标题画面右侧窗口显示 PocketRoles 面板即安装完成。之后 **在线 → 创建房间** 就能启用职业。

详细步骤和手动安装见 [第 5 章](#5-安装步骤steam)，启动器的用法见 [第 6 章](#6-启动器与更新)，玩法见 [第 7 章](#7-游玩方法)。

## 如何招人

根据 2026 年 7 月起的官方规则，使用 MOD 的房间必须向服务器注册（MOD 房间注册，PocketRoles 会自动完成）。已注册的房间 **不会出现在公开列表里**，需要房主把房间代码告诉玩家（[第 3 章](#3-innersloth-模组政策与公开房间须知必读)）。代码怎么分享都可以，贴到你平时用的地方即可：

- **Discord 服务器**：贴上房间代码就行（复制房主画面上显示的代码再粘贴。在聊天里输入 `/announce` 会复制到剪贴板）
- **微信・QQ 群**
- **朋友**（直接告诉）

没有社群、想从公开列表招路人的话，就用 **副手机等开一个原版公开房“引导房”**（名字改成“职业→代码”）。这是唯一能从公开列表把人引进来的入口：

1. **在 PC 上创建职业房**（和平时一样，注册保持开启）。房间代码显示在房间画面下方（原版的房间代码栏）；输入 `/code on` 也可以在左上角 **大字显示**，例如“职业房 QWERTY”（默认关闭）。在聊天里输入 `/announce`，代码会复制到剪贴板，并显示下面的步骤。
2. **在副手机的 Among Us（原版）里把名字改成“职业→QWERTY”**（代码换成自己房间的）。
3. **用副手机创建一个公开房间**（无模组的普通房间）。在聊天里写“有职业的房间是 QWERTY”。
4. 从公开列表进来的人看到名字里的代码后，**转到 PC 的职业房**。重建房间导致代码变化时，改一下手机的名字（`/announce` 可以再次复制）。

例：PC 的房间代码是 `QWERTY` → 副手机的名字是 `职业→QWERTY`，引导房的聊天写“有职业的房间是 QWERTY，输入代码来玩吧”。详见 [第 25 章](#25-便利房关闭注册与引导房)。

> **注意**：短时间内反复重建房间、或在对局中途退出，官方服务器会视为“故意断线”并累加 **ban points**，可能暂时无法创建房间。只在必要时重建房间（[3.4](#34-关于封禁与踢出)）。

没有邮件客户端也没关系，用浏览器里的 Gmail 等网页邮箱发送即可（zip 从桌面添加为附件）。回复可能需要几天。

## 功能一览

- 新增 26 个职业：警长、市长、告密者、点灯人、增速者、诱饵、内鬼狂粉、狂粉市长、疯狂特技演员、鹰眼狂粉、崇拜者、吸血鬼、黑手党、女巫、刺客、邪恶鹰眼、邪恶猫又、连环杀手、武士、小丑、投机者、恐怖分子、豺狼、豺狼之友、恋人、纵火犯
- 职业通过每位玩家自己的 **名字标签** 和 **聊天** 私下告知本人
- 设置在 **房间设置界面的“PocketRoles”标签页**（职业 / 房间 / 聊天 / 外观 / 房主 分页，带“?”帮助；原版的 3 个按钮折叠为“▶ 原版设置（游戏・预设・职业）”）和 **齿轮菜单的“PocketRoles 设置”面板** 中完成（也可以用聊天命令 `/set` `/opt` 或配置文件）
- 显示语言：**日本語 / 简体中文 / English**。每位玩家可用 `/lang` 单独切换（也会根据发言语言自动识别），文本可在 `lang\*.json` 中编辑
- **聊天自动翻译**（默认开启，**并用模式**）：把外语聊天翻译成房主的语言发给所有人，把房主的话按各自的语言单独发给外语玩家（使用 Google，或 DeepL 的 API 密钥）
- **招人辅助**：复制房间代码并显示引导步骤（`/announce`，复制的代码可直接贴到 Discord 等）、房间代码大字显示（`/code on`，默认关闭）、从便利房引导到职业房（`/move`）
- 房主工具：房间剩余时间显示、自动开始、废村（刷新房间）、开始取消按钮、强制结束会议、快捷键（F7 / F8 / F9）、房主分页的操作按钮、游戏主持（观战）模式、镜像 Skeld（Dleks）、延迟过高时询问是否重建
- **协作管理（权限）**：管理员 / 版主 / VIP / 封禁，通过 `Admin.txt` 等文件和 `/admin` `/kick` `/ban` 管理。管理员可使用设置命令，版主可踢人
- **原版设置范围扩展**：击杀冷却、投票 / 讨论时间、紧急会议冷却、任务数可以超出原版上下限（设置界面的箭头和 `/vset`。原版玩家也会收到同样的数值）
- 仅房主屏幕可见的外观自定义（替换帽子、面罩、名牌，大厅 BGM、墙画、菜单背景、鼠标光标），标题画面的 PocketRoles 面板
- 自动重建房间、自动公开、欢迎语与规则行编辑、测试模式（1 人即可开始）、游戏版本检查、`/diag` 诊断
- **启动器**（PocketRoles Launcher）：给朋友用的安装器（复制 Steam 版 → BepInEx → PocketRoles 全自动）、检查更新、启动、生成问题报告 zip。日本語 / 中文 / English
- BepInEx 6（IL2CPP）插件，C# / .NET 6，Harmony

## 1. 概述（工作原理）

被修改的只有房主的 Among Us。原版客户端会原样显示“房主发来的信息”，所以房主向每位玩家发送 **不同的内容**（职业、名字标签、聊天、游戏设置），就实现了自定义职业。

- 击杀判定、跳管、破坏、投票统计、胜负判定全部在房主端进行。
- 警长、豺狼、纵火犯和崇拜者在自己的客户端上以“内鬼”身份运行（为了拥有击杀键），而在其他所有人眼中是“船员”。
- 内置了防止会议后原版客户端画面卡死（黑屏）的处理。
- v0.4 的房主工具（自动开始、废村、结束会议、快捷键等）**全部使用原版机制**（开始倒计时、游戏结束、投票截止），所以玩家一方只会看到聊天提示和正常的游戏流程。
- 原版设置范围扩展（v0.4b）同样直接使用原版的设置同步。房主在设置界面选择的数值（例如击杀冷却 5 秒）会原样显示在玩家的房间设置列表中。
- 聊天翻译（v0.4b）由房主的电脑把文本发送到 Google / DeepL 进行翻译。默认开启，以 **并用模式** 运行（外语聊天翻译成房主的语言发给所有人，房主的话单独翻译给外语玩家）。不想把文本发到外部时，可在设置标签页“聊天”分页的“聊天翻译”或用 `/opt translate off` 关闭（[第 13 章](#13-语言日本語--中文--english)）。
- 只有 **开启了 MOD 房间注册的房间** 才能分配职业。未注册的房间（便利房）中，只要向单个玩家发送一条消息房主就会被服务器断开，因此那里的职业和私密通知全部停用，只在原版对局之上保留房主工具（[第 25 章](#25-便利房关闭注册与引导房)）。
- 房主屏幕左上角（ping 显示处）显示 `PocketRoles v0.5.0 (host) · 亚洲` 这样带当前区域名的一行，在线房间中还显示 `房间剩余 mm:ss`（`/code on` 后还会大字显示房间代码 `职业房 ABCDEF`，默认关闭），游戏内的模组标记也会显示。标题画面右侧的大窗口中显示 **PocketRoles 面板**（图标、`v0.5.0 / Among Us 2026.8.18`、作者名、可点击的 GitHub 行、“仅房主安装即可游玩职业”“参与者无需安装即可加入”）（[第 9 章](#9-齿轮菜单的pocketroles-设置面板)）。
- 仅支持 **经典模式**（躲猫猫 / Seek Fools 模式下模组不做任何事）。

原版玩家实际看到的效果汇总在 [第 26 章](#26-原版玩家看到的是什么)。

## 2. 新功能（v0.2 / v0.3 / v0.4）

### v0.4e（v0.4.0 的收尾：引导房、便利房、翻译并用）

- **引导房辅助**（[第 25 章](#25-便利房关闭注册与引导房)）：房间左上角大字显示房间代码（`职业房 ABCDEF`。默认关闭，`/code on` 开启，`/code` 切换，设置标签页“大字显示房间代码”）。`/announce`（`/guide`）把代码复制到剪贴板（可直接贴到 Discord 等），并显示用副手机做引导房的 4 个步骤。`/move [代码]` 在便利房里用三种语言向所有人发送职业房的引导（`/opt guide.autoreg on` 时 30 秒后重建为注册房间）。齿轮菜单里也有引导房提示。
- **便利房（关闭注册）的整理**：实机测试发现，未注册的房间中只要向单个玩家发送一条消息，房主就会被服务器断开（"DC because Hacking"）。因此未注册的房间 **不分配职业，按原版进行**（只有房主工具和面向所有人的提示）。要玩职业请用注册开启（默认）的房间。
- **翻译并用为默认**（`BroadcastToAll = true` + `TranslateForPlayers = true`）：外语聊天翻译成房主的语言发给所有人；房主的话按各自的语言单独发给选择了其他语言的玩家；同一个人不会收到两份。翻译本身（`Enabled`）也默认开启（聊天文本会发送到 Google；如果在 `BepInEx\PocketRoles\deepl-key.txt` 放了密钥则发送到 DeepL）。可在设置标签页的“聊天翻译”或用 `/opt translate off` 关闭。
- **延迟过高时先询问**：创建房间后延迟过高时，房主屏幕会弹出“延迟较高（N ms）。要重新创建房间吗？”（是 / 否，也可用 `/rehost yes|no`）。默认关闭（`MaxHostPing = 0`），因为短时间内反复重建会累加 ban points（[3.4](#34-关于封禁与踢出)）。
- **设置标签页**：分页按钮改为“职业 / 房间 / 聊天 / 外观 / 房主”的短标签横向一排。原版的 3 个按钮初始折叠为“▶ 原版设置（游戏・预设・职业）”，点击展开为“▼ 原版设置”。“房主”分页上方有操作按钮行（立即开始 / 取消 / 废村 / 结束会议 / 测试模式 / 显示设置）。
- **修正职业分配**：修复了 2 人以上开局时没有开场动画、画面全黑的问题（原样放行游戏本体的职业广播，随后一次性覆盖所有客户端的显示）。警长、豺狼的开场动画仍显示为“内鬼”（从 v0.4.1 起职业通知会多一行“※游戏本体显示你是“内鬼”（开场、击杀键），但你的真正职业是○○。”）。
- **测试模式**：`/test on` 后开始按钮立即变为“开始”，游戏本体的“4 人可以游玩，但…”弹窗也会自动确认。
- **语言文件**：更新新增的键会在启动时追加到 `lang\*.json`（自己编辑过的文字保持不变）。
- **日志**：平时保持安静。`/diag on` 开启开局流程的详细追踪，`/diag` 输出状态快照。

### v0.4c（v0.4.0 的修正：实机测试中发现的问题）

- **延迟过高时重建房间**（`[Lobby] MaxHostPing`，`/opt maxping <ms>`，0 = 关闭）：创建房间后的 5 秒内，到服务器的延迟一直高于上限且还没有人加入时，用相同设置重新创建房间（最多连续 3 次；聊天中会显示原因和新房间代码）。官方亚洲区域混有近的服务器（8〜10 ms）和远的服务器（70 ms 以上），这是针对远服务器的对策。自动选择区域仍默认关闭。**v0.4e 起改为必须先询问房主，默认也改为关闭（0）**（[第 15 章](#15-自动重建房间与自动公开)）。
- **`/diag`**（仅房主）：把开始按钮、测试模式、废村、对局状态和画面（飞船、开场动画、HUD）的快照输出到聊天和日志。画面一直黑屏时请用它报告。开局流程的每一步也会以 `Trace:` 记录到日志。
- **F9 取消在聊天输入中也有效**：刚输入 `/start` 后（光标还在输入框里）只要在倒计时中就能用 F9 取消（F7 / F8 在输入中仍然无效）。第一次按 F7 时“在 3 秒内再按一次 F7…”也会显示在聊天中；开局后 10 秒以上画面仍未出现的对局，按一次 F7 即可结束。
- **房间剩余时间横幅**：原版红色的“房间将在 ○ 秒后关闭”只在打开设置界面（房间里的电脑）期间隐藏，关闭后恢复（其他时候照常显示；与 PocketRoles 的“房间剩余 mm:ss”是分开的）。
- **PING 行显示区域名**：左上角的一行变为 `PocketRoles v0.4.0 (host) · 亚洲`，带有当前连接区域的名称（游戏语言）。
- 其他：`/test on` 后开始按钮立即变为“开始”；废村或“再玩一次”之后不再残留上一局的状态（第二次 `/start` 黑屏的对策）；废村后的结束画面自动进入“再玩一次”；标题画面右侧窗口上方新增“打开 GitHub”按钮。

## 3. Innersloth 模组政策与公开房间须知（必读）

### 3.1 创建房间时必须进行“MOD 房间注册”

Innersloth 的 Among Us Mod Policy（<https://www.innersloth.com/among-us-mod-policy/>，Last Modified July 30, 2026）中有以下条款：

> "Any mod that changes the functionality of Among Us on official servers must be registered on lobby creation. A change of functionality includes but is not limited to making modifications to gameplay, custom role behavior, cheating, or modifying any part of a peer's experience."

（凡是在官方服务器上改变 Among Us 功能的模组，都必须在创建房间时注册。功能改变包括但不限于修改游戏玩法、自定义职业行为、作弊，以及改变其他玩家体验的任何部分。）

PocketRoles 添加了职业并改变其他玩家的体验，因此在官方服务器上使用时 **必须在创建房间时进行 MOD 房间注册（即所谓的 +25）**。
房主专用模组的注册方式是在协议版本号上加 25，即“host authority mode”，Innersloth 的官方资料 <https://github.com/Innersloth-LLC/AmongUsModdingInformation> 中有说明。PocketRoles **默认会这样做**（设置 `RegisterAsModdedLobby = true`。只在自己创建房间时附加，加入别人的房间时不附加）。

注册后：

- 服务器会把玩家发送的以 `/cmd …` 开头的聊天 **只转发给房主**。玩家能像 `/cmd n` 这样 **私下** 使用命令就是因为这一点。
- 大部分游戏玩法方面的校验交给房主处理，房主因模组通信被判定为“hacking”而踢出的概率更低。

### 3.2 已注册的房间不会出现在公开房间列表中

Innersloth 帮助中心（<https://innersloth.zendesk.com/hc/en-us/articles/6711746215700-Are-there-mods-for-Among-Us>）写道："modded games are not able to be found via public lobby search, so if you're hosting a modded game, you'll need to invite friends directly"（模组房间无法通过公开房间搜索找到，如果你在开模组房，需要直接邀请好友）。
已注册的 PocketRoles 房间 **不会出现** 在原版的公开房间列表中（已用手机版确认），设为“公开”也一样。请在 Discord 服务器、微信・QQ 群或直接向朋友告知 **房间代码**，或使用 [引导房](#25-便利房关闭注册与引导房)（用副手机等开一个原版公开房，名字写成“职业→代码”。适合从公开列表招路人）。

参考：日本的模组（TOH-Y、TOH-K、SuperNewRoles 等）在 2023 年因“原版玩家不知情地进入模组房间”的问题收到 Innersloth 的通知，此后在官方服务器上禁用了公开房间。

技术补充（分析 2026.8.18 客户端的结果）：原版“查找房间”界面的筛选器中有一个模组用的项目（ModFilter），它是给“所有人都安装同一模组”的 GUID 注册型模组用的。原版客户端不会附加这个筛选器，因此已注册的房主专用模组房间会被服务器从列表中排除。客户端一侧没有既保持注册又出现在列表中的办法。

### 3.3 关闭注册 = 无职业的“便利房”

以 `RegisterAsModdedLobby = false`（`/opt register off`、设置标签页中的“MOD房间注册（官方规则・职业必需）”、齿轮面板的“MOD房间注册”）创建的房间会出现在公开列表里，但 **不会分配职业**。

- 未注册的房间中，服务器会把“只发给某一个玩家的消息”视为作弊并 **断开房主**（实机确认："DC because Hacking"）。职业的私密通知无法成立，因此 PocketRoles 在未注册的房间里停用职业、名字标签和所有私密消息，只在原版对局之上保留房主工具（剩余时间、自动开始、废村、结束会议、面向所有人的翻译等）。这相当于 AUR 那样的“实用工具模组”用法，不改变游戏玩法，所以政策上不需要注册。
- 也没有 `/cmd` 私密频道，玩家的命令所有人都能看到。
- 想玩职业请创建 **注册开启（默认）** 的房间。招人的方法见 [如何招人](#如何招人)（在 Discord 等分享代码）和 [第 25 章](#25-便利房关闭注册与引导房)（引导房、`/move`）。

`/opt register on` 可以恢复（从下一个创建的房间起生效）。

### 3.4 关于封禁与踢出

Innersloth 表示，只要不妨碍他人的体验，仅使用模组不会封号。另一方面，自动反作弊导致的 **踢出** 在房主专用模组中很常见（尤其是人多、通信量大的时候）。PocketRoles 把发送分散到每 0.1 秒一次并保持数据包很小，但并不能完全避免。被断开时可以使用 [自动重建房间](#15-自动重建房间与自动公开)。

**注意 ban points（短时间内退出）**：官方服务器会把“创建房间后马上退出”“对局中途退出”“短时间内反复重建房间”等行为计为“故意断线”（ban points。实机测试中累计到 3.5 时显示“因故意断开连接而受到限制”，一段时间内无法创建房间）。这与模组功能无关，原版房主也一样。重建房间（自动重建、`/move`、延迟过高时的重建）只在必要时使用，优先用废村（同一房间重置时间）。

## 5. 安装步骤（Steam）

无论哪种方法，都是把 Steam 的游戏文件夹 **复制到另一个位置**，再把 BepInEx 和模组放进去。这样 Steam 版仍保持原版，可以正常加入别人的房间，Steam 的自动更新也不会破坏模组环境。

### 5.1 推荐：用启动器安装（PocketRoles-Setup zip）

1. 从 GitHub Releases（<https://github.com/wakayamachannel/PocketRoles/releases>）下载 **`PocketRoles-Setup-<版本>.zip`**。
2. 解压到一个不会删除的文件夹（例如 `文档\PocketRoles`）。**把 `PocketRoles-<版本>.zip`（模组本体）也放进同一个文件夹（解压与否都可以）**，没有网络也能安装。桌面快捷方式会指向这个文件夹，之后请不要移动或删除。
3. **双击“PocketRoles Launcher.cmd”**。首次运行如果出现“Windows 已保护你的电脑”（SmartScreen），请点 **“更多信息”→“仍要运行”**。这是因为没有使用签名证书，不是病毒。
4. 点击启动器的 **“安装”**。它会自动完成以下步骤（需要几分钟，进度显示在下方）：
   1. 查找 Steam 版 Among Us（找不到时会让你选择文件夹），复制到 `桌面\Among Us PocketRoles`（1 GB 左右）。如果桌面由 OneDrive 备份，则改为复制到 `%LOCALAPPDATA%\PocketRoles\Among Us PocketRoles`（参数 `-GameDir` 可以选择任意文件夹）
   2. 从 builds.bepinex.dev 下载 BepInEx 6.0.0-be.735（win-x86）并解压
   3. 从 GitHub 的最新发布获取 `PocketRoles-<ver>.zip` 并放置（把 `PocketRoles-<ver>.zip` 放在启动器同一文件夹中即可离线安装）。如果有旧的 `HostRoles.dll` 会删除
   4. 在桌面创建“PocketRoles Launcher”快捷方式
5. **先启动 Steam，再点“启动”**。首次启动时 BepInEx 需要生成 interop，到标题画面大约 **1〜2 分钟**（中途可能出现黑色控制台窗口，请不要关闭）。
6. 标题画面右侧出现 PocketRoles 面板、左上角显示 `PocketRoles v0.5.0` 即安装完成。

如果某个步骤失败，修正原因（网络连接、Steam 位置等）后再点一次“安装”，已完成的步骤会跳过，从失败处继续。启动器右上角的“语言”可切换 日本語 / 中文 / English。随附的 `はじめに.txt` 用三种语言写了同样的步骤。

### 5.2 手动安装

1. 把 `C:\Program Files (x86)\Steam\steamapps\common\Among Us` 整个复制到另一个文件夹（例如 `桌面\Among Us PocketRoles`）。
2. 把上面的 BepInEx zip 解压到复制的文件夹中（`Among Us.exe` 同级目录下应有 `winhttp.dll`、`doorstop_config.ini` 和 `BepInEx\` 文件夹）。
3. **在 Steam 已启动的状态下**，把复制出来的 `Among Us.exe` **运行一次**。首次运行时 BepInEx 会生成 `BepInEx\interop`，出现标题画面需要 **1〜3 分钟**。出现标题画面后可以关闭。
4. 把 GitHub Releases 的 `PocketRoles-<ver>.zip` 解压到复制的文件夹中（包含 `BepInEx\plugins\PocketRoles.dll`、`BepInEx\PocketRoles\lang\*.json`、README、LICENSE 和 NOTICE）。**如果还留有旧版的 `HostRoles.dll`，请删除**（同样的补丁会被应用两次）。
5. 运行复制出来的 `Among Us.exe`（不要从 Steam 库启动，而是直接运行复制目录中的 exe，同时保持 Steam 运行）。屏幕左上角出现 `PocketRoles v0.5.0`、标题画面右侧窗口出现 PocketRoles 面板即表示模组已加载。也可以通过 `BepInEx\LogOutput.log` 中的 `PocketRoles v0.5.0 loaded` 来确认。

首次启动时会生成 `BepInEx\config\jp.pocketroles.mod.cfg`（配置）、`BepInEx\PocketRoles\lang\`（语言文件）、`BepInEx\PocketRoles\{hats,visors,nameplates,music,images}\` 和 `README.txt`（外观自定义用）。权限文件 `Admin.txt` / `Moderator.txt` / `VIP.txt` / `Banlist.txt` 会在第一次创建房间时生成在 `BepInEx\PocketRoles\` 中。使用 DeepL 时的 `deepl-key.txt` 需要自己创建（[第 13 章](#13-语言日本語--中文--english)）。如果同一文件夹中有旧 HostRoles 的配置 `jp.hostroles.mod.cfg` 而新配置文件尚不存在，内容会自动复制过来（设置原样继承）。

### 开发者电脑上的目录结构（参考）

- 模组用副本：`桌面\Among Us PocketRoles`

## 6. 启动器与更新

### 6.1 PocketRoles Launcher 的两种模式

通过桌面上的 **“PocketRoles Launcher”** 快捷方式（实体是 `PocketRoles Launcher.cmd` → `PocketRolesLauncher.ps1`）启动的小型图形界面（PowerShell 5.1 / WinForms，不需要管理员权限，启动器 v0.4.0）。启动时会自动进入两种模式之一。

| 模式 | 何时 | 功能 |
|---|---|---|
| **朋友模式（安装器）** | 启动器旁边 **没有** `PocketRoles.csproj` 时（解压 `PocketRoles-Setup-<ver>.zip` 的情况） | 安装 / 检查更新 / 启动 / 生成报告 zip / 打开设置文件 / 打开日志 / 说明书 (README) / 打开 mod 文件夹 |
| **开发模式** | 在源代码目录中启动时（旁边有 `PocketRoles.csproj`） | 带 mod 启动 / 检查 / 更新游戏（复制 → interop → 重新编译）/ 仅重新编译 / 检查 GitHub 更新 / 启动原版 (Steam) / 打开设置文件 / 打开日志 / 说明书 (README) / 打开 mod 文件夹 / 生成报告 zip |

共同点：右上角的 **“语言”** 可切换 日本語 / 中文 (简体) / English（首次根据 Windows 显示语言自动判断，选择保存在 `launcher-state.json`）。上方是状态，中间是按钮，下方是进度日志。处理期间按钮会被禁用。模组副本的位置是 `桌面\Among Us PocketRoles`（开发模式下优先使用源代码旁边的 `..\Among Us PocketRoles`），可以用环境变量 `POCKETROLES_GAMEDIR` / `POCKETROLES_STEAMDIR` 或参数 `-GameDir` / `-SteamDir` 更改。

状态显示：

| 显示 | 含义 |
|---|---|
| Steam 版 Among Us / mod 副本 | 从两个游戏文件夹中读取的版本。不一致时 **Steam 版已更新**（橙 / 红字） |
| BepInEx | 已安装的版本（be.735 为 OK，否则需要更新）。开发模式下显示“BepInEx / interop”是否存在 |
| PocketRoles.dll | 已安装的版本和时间（开发模式下还有构建时对应的游戏版本，不一致时 **需要重新编译**） |
| interop (首次启动时生成) | 首次启动生成的 `BepInEx\interop` 是否存在 |
| .NET SDK (重新编译用) | 仅开发模式。`%USERPROFILE%\.dotnet\dotnet.exe` 是否存在 |
| Steam 客户端 | 是否正在运行（游玩和生成 interop 都需要 Steam） |

绿字显示“准备就绪”（开发模式为“已是最新”）时即可直接游玩。

| 按钮 | 动作 |
|---|---|

## 7. 游玩方法

1. 用启动器的“启动”（开发模式为“带 mod 启动”。或模组副本中的 `Among Us.exe`）启动游戏（Steam 运行中）。
2. **在线 → 创建房间**（游戏模式选 **经典**，注册保持开启）。区域照常选择。
3. 打开房间里的笔记本电脑（设置界面），点击左侧的 **“PocketRoles”** 按钮设置职业人数等（[第 8 章](#8-设置标签页房间设置界面)）。用聊天命令 `/set sheriff 1` 或 `/opt sheriff.cooldown 25` 也能做同样的事，两种方式都会立即保存到配置文件。初始设置为警长 1、小丑 1、内鬼狂粉 1。
4. 招人。把房间画面下方显示的 **房间代码** 贴到 Discord 服务器、微信・QQ 群，或直接告诉朋友（`/announce` 复制代码后直接粘贴即可；`/code on` 可以在左上角大字显示）。没有社群、想招路人时，抄到副手机的 **引导房** 里（[第 25 章](#25-便利房关闭注册与引导房)）。加入的玩家几秒后会收到 **只发给本人** 的三语简短聊天消息，说明这是职业模组房间（什么都不用装，职业显示在自己名字上方）以及如何查看职业说明（`/cmd r 职业名`）（[第 14 章](#14-加入时的欢迎语与规则行)）。
5. 设置标签页“聊天”分页的 **聊天翻译** 默认开启（外语聊天会翻译成你的语言发给所有人，外语玩家会收到你的话的对应语言翻译。聊天文本会发送到 Google / DeepL，不需要的话用 `/opt translate off` 关闭。[第 13 章](#13-语言日本語--中文--english)）。
6. 等待期间屏幕左上角会显示 `房间剩余 mm:ss`。人数齐了就按 Start，或交给自动开始（`/autostart <人数>`）。剩余时间不多时模组会自动延长 / 废村，不用担心房间关闭（[第 16 章](#16-房间剩余时间自动开始与废村)）。
7. 开始游戏。开始几秒后，每位玩家会通过聊天收到职业名称和说明，自己的名字上方会显示职业名（会议中在名字旁边小字显示）。普通职业的玩家只会收到“本局有特殊职业”的提示。
   - 参与者可用 `/cmd n` 查看自己的职业，`/cmd r <职业名>` 查看职业说明，`/cmd h` 查看帮助，`/cmd time` 查看房间剩余时间，`/cmd lang en` 更改自己的语言（已注册的房间中 `/cmd …` 只有房主能收到）。
   - 每次会议开始时会重新发送职业说明（`RoleInfoAtMeeting`）。
8. 游戏结束回到房间后，所有人的职业和获胜者列表会出现在聊天中。用 `/cmd l` 可以再次查看。

提示：

- 按下 Start 后如果出现“等待玩家同步”，请稍等几秒后再按一次（这是为了防止在同步完成前开始而被服务器踢出的保护）。
- 开始倒计时期间想取消时，“取消”按钮、F9、Esc、`/cancel` 都可以（[第 17 章](#17-快捷键与取消按钮)）。
- 会议拖得太久时按两次 F8（或 `/endmeeting`）即可截止投票（[第 18 章](#18-强制结束会议)）。
- 想立即结束游戏并回到同一房间时按两次 F7（或 `/haison`）。
- 设置标签页“房主”分页的上方也有 **立即开始 / 取消 / 废村 / 结束会议 / 测试模式 / 显示设置** 按钮（只用鼠标即可操作）。
- 想临时玩原版时用 `/mod off`（从下一局起生效），`/mod on` 恢复。
- 正式开房前，建议用手机等另一台设备通过 [测试模式](#23-测试模式用一台手机验证) 确认运行情况。
- 希望被服务器断开时自动重建房间，请用 `/rehost on`（[第 15 章](#15-自动重建房间与自动公开)）。重建后代码会变，记得重新告诉玩家（用引导房的话也改一下它的名字）。
- 有一起管理房间的朋友时，用 `/admin add <名字>` 设为管理员，那个人也能使用 `/set`、`/kick` 等命令（[第 11 章](#11-命令一览)）。
- 想把击杀冷却设到 10 秒以下、讨论时间设到 2 分钟以上时，设置界面的箭头可以直接超出原版范围（也可以用 `/vset killcd 5`。[第 8 章](#8-设置标签页房间设置界面)）。
- 画面一直黑屏不动时，输入 `/diag` 会把状态输出到聊天和日志，请连同报告 zip 一起发送（[第 28 章](#28-如何报告问题)）。

### 原版设置范围扩展（v0.4b，`[Vanilla]`）

原版“游戏设置”标签页中的数值有上下限（击杀冷却 10〜60 秒、投票时间 15〜300 秒、讨论时间 0〜120 秒、紧急会议冷却 0〜60 秒、任务数 普通 0〜2 / 短 0〜5 / 长 0〜3）。`ExtendedRanges = true`（默认开启。设置标签页“原版设置范围扩展”，`/opt vanilla.ranges on|off`）后，房主设置界面中 **这些行的箭头可以超出原版范围**。

| 项目 | 原版范围 | 扩展后的默认范围 | 设置键（设置标签页项目） |
|---|---|---|---|
| 击杀冷却 | 10〜60 秒，步长 2.5 | **0〜120 秒**，箭头步长默认 2.5（把 `KillCooldownStep` 调低到 0.5 或用 `/vset` 即可设置 0.5 秒单位的值） | `KillCooldownMin`（0〜60）/ `KillCooldownMax`（10〜600）/ `KillCooldownStep`（0.5〜10，默认 2.5） |
| 投票时间 | 15〜300 秒 | **0〜600 秒**（0 = 没有投票阶段） | `VotingTimeMin`（0〜300）/ `VotingTimeMax`（15〜3600） |
| 讨论时间 | 0〜120 秒 | **0〜600 秒** | `DiscussionTimeMax`（0〜3600） |
| 紧急会议冷却 | 0〜60 秒 | **0〜120 秒** | `EmergencyCooldownMax`（0〜600） |
| 普通 / 短 / 长任务数 | 0〜2 / 0〜5 / 0〜3 | **0〜30**（三者共用） | `TaskCountMax`（1〜60） |

- 范围 **只会放宽不会收窄**。数值通过与原版相同的路径（设置更改 → 设置同步）发送，因此 **原版玩家的房间设置列表中会显示同样的数字，游戏中也按该值运行**。玩家一方不需要任何东西。
- 聊天中可以用 `/vset <项目> <值>` 直接设置（仅在房间中）。项目：`killcd`（`kill` `cooldown`）、`vote`、`discuss`、`emergency`、`common` / `short` / `long`（任务数）、`speed`（移动速度 0.25〜5 倍）、`vision`（船员视野 0.1〜10 倍）、`impvision`（内鬼视野 0.1〜10 倍）。`/vset show` 显示当前值。速度和视野的扩展是固定范围，只能通过 `/vset` 设置（不会放宽设置界面的行）。
- 设置界面打开时，`/vset` 的值会立即反映到对应行，箭头从该值继续。预设会变为“自定义”。
- 注意：极端的值（投票 0 秒、击杀冷却 0 秒、任务 30 个等）可能出现原版没有考虑到的行为。正式开房前请用手机测试。游戏设置中“投票时间 0”会跳过投票阶段。

## 11. 命令一览

在聊天中输入。格式为 `/cmd <命令> …` 或 `/<命令> …`。设置的修改也可以在 [设置标签页](#8-设置标签页房间设置界面) 或 [齿轮面板](#9-齿轮菜单的pocketroles-设置面板) 中进行。

- **在已注册的房间中，`/cmd …` 只有房主能收到**（玩家查询自己的职业时用这种写法）。
- 像 `/n` 这样不加 `/cmd` 的写法会作为普通聊天 **让所有人看到**（回复只发给本人）。玩家不加 `/cmd` 输入了未知命令时，会按普通聊天处理。
- 房主自己输入的命令无论哪种写法都不会发送出去，回复只显示在房主的画面上。
- 每位玩家的命令每 2 秒最多 1 次。每条命令的回复最多 3 条消息（`/cmd s` 的设置列表为 4 条，欢迎语预览为 4〜5 条），并且使用 **该玩家的语言**。
- 列在 `Admin.txt` 中的玩家（管理员）可以使用部分房主专用命令，`Moderator.txt` 中的版主可以使用 `/kick` `/ban`（v0.4b，见下方“权限”）。其他人输入房主专用命令会得到“仅限房主。”

### 禁用命令（v0.4）

| 设置 | 效果 |
|---|---|
| `[Chat] PlayerCommands = false`（设置标签页“玩家命令”关闭，齿轮面板“禁用玩家命令”） | 玩家的命令（`/cmd …` 和已知的 `/…`）会被忽略，并在该房间中对每人只回复一次“本房间无法使用聊天命令（房主已禁用）。”未知的 `/…` 仍按普通聊天处理。房主的命令可以使用 |
| `[Chat] AllCommands = false`（“全部命令”关闭，“禁用全部命令”） | 房主也只能使用 `/mod on|off`（其他命令回复“命令已禁用（设置“全部命令”为关闭）。只能使用 /mod on|off。…”）。玩家的命令同上被忽略。可在设置标签页或齿轮面板中恢复 |

### 权限（协作管理）：管理员 / 版主 / VIP / 封禁（v0.4b）

用于和朋友一起管理房间。通过 `BepInEx\PocketRoles\` 中的 4 个文本文件管理（第一次创建房间时会带说明头生成）。

| 文件 | 权限 | 可以做的事 |
|---|---|---|
| `Admin.txt` | 管理员 | `[Permissions] AdminsCanChangeSettings = true`（默认）时，可使用房主专用命令中的 **`/set` `/opt` `/show` `/start` `/cancel` `/autostart` `/welcome` `/rules` `/kick` `/ban` `/unban` `/vset` `/vip …` `/mod add|remove|list`**（`/mod on|off`、`/test`、`/assign`、`/end`、`/rehost`、`/public`、`/haison`、`/endmeeting`、`/results`、`/region`、`/cos`、`/reload`、`/reset`、`/admin` 仅限房主）。回复只发给本人，日志会记录是谁执行的 |
| `Moderator.txt` | 版主 | `[Permissions] ModeratorsCanKick = true`（默认）时，可使用 `/kick <名字>` 和 `/ban <名字>`（`/ban list` / `remove` 需要管理员以上） |
| `VIP.txt` | VIP | `[Permissions] VipMarker = true`（默认）时，游戏中名字标签的开头会带 **★**（所有人的画面），加入时欢迎语中多一行“★ 欢迎 VIP ○○！感谢一直以来的支持。” |
| `Banlist.txt` | 封禁 | 加入的瞬间（约 0.5 秒后）被踢出（模组启用的房间中） |

- 格式：**每行一人**，好友代码（`name#1234`）或 Puid。`//` 之后是备注（用 `/admin add` 添加时会写成 `<标识> // <名字> <日期>`）。以 `//`、`;`、`#` 开头的行是注释。不区分大小写。
- 文件 **修改时间变化时会自动重新读取**，可以在游戏运行中直接编辑（`/admin reload` 等可强制重新读取）。
- 等级顺序：房主 > 管理员 > 版主 > VIP > 普通。踢出 / 封禁 **只能针对等级比自己低的人**（版主不能踢管理员，房主不会被任何人踢）。
- 指定玩家时可以用编号（`#3` / `3`）、好友代码 / Puid、完整名字、能唯一匹配的部分名字（与 `/assign` 相同）。
- 由于通过好友代码 / Puid 识别，**本地（局域网）房间中无法使用**（没有识别信息）。
- `/h` 的末尾会显示该玩家的权限（例如“你的权限：版主（版主可以使用 /kick 和 /ban）”）。没有权限的人输入房主专用命令时，“仅限房主。”后面会附上原因。
- 可以通过设置标签页“房主工具”分页中的“允许管理员更改设置”“版主可踢人/封禁”“VIP 名字加★”，或 `/opt perm.adminsettings|perm.modkick|perm.vipmarker on|off` 逐项关闭（文件保持不变）。

## 12. 配置文件

`BepInEx\config\jp.pocketroles.mod.cfg`（首次启动时自动生成。设置标签页、齿轮面板和 `/set` `/opt` 修改的值会立即保存到这里。可以在关闭游戏的状态下用文本编辑器编辑，或者编辑后在房间中执行 `/reload`）。实际文件中各分区按字母顺序排列。

```ini

RegisterAsModdedLobby = true    # MOD 房间注册（即所谓的 +25）。官方规则要求、职业必需。off 违反政策
IgnoreVersionMismatch = false   # 即使游戏版本与支持版本（2026.8.18）不同也运行模组（风险自负）
GameMaster = false              # 游戏主持：房主不持有职业，开场动画后立即死亡，只观战 / 主持

[Chat]
WelcomeMessage = true           # 向加入的玩家发送模组房间说明
RoleInfoAtMeeting = true        # 会议开始时重新发送职业说明
WelcomeText =                   # 欢迎语（空 = 默认）。\n 换行，可插入 {rules} {roles} {settings} {help} {version}
WelcomeIncludeSettings = false  # 在欢迎语中附加当前职业设置（默认关闭。随时可用 /cmd s 查看）
PlayerCommands = true           # 允许玩家使用聊天命令（false = 忽略并只提示一次）
AllCommands = true              # 允许所有聊天命令（false = 房主也只能用 /mod）
RulesMode = none                # 欢迎语规则行：none（默认的“无规则”）| custom（RulesText）
RulesText =                     # custom 时的规则文字（\n 换行，/rules <文字>）
WelcomeAllLanguages = true      # 把简短欢迎语（2 行）按 该玩家的语言 → 其余两种语言 的顺序发送（false = 只发该玩家的语言 + 一行三语 /lang 提示）

[Translate]                     # 聊天翻译（v0.4b）。文本会发送到 Google / DeepL。DeepL 密钥不写在这个文件里
Enabled = true                  # 翻译外语聊天（默认开启。文本会发送到 Google / DeepL。在设置标签页“聊天翻译”或用 /opt translate off 关闭）
Provider = auto                 # auto（BepInEx\PocketRoles\deepl-key.txt 有密钥则 DeepL，否则 Google）| google | deepl
TargetLang =                    # 房主阅读的语言 ja | zh | en（空 = [General] Language）
ShowOnHost = true               # 在房主屏幕显示翻译（不发送）
BroadcastToAll = true           # 把外语聊天翻译成房主的语言发送给所有人（会收到单独翻译的玩家除外）
TranslateForPlayers = true      # 把聊天翻译成用 /lang 选择了外语的玩家的语言并单独发送（两者都为 true = 并用，默认）
AutoDetectLang = true           # 未设置 /lang 的玩家用中文或英文发言时自动切换其显示语言（仅一次）
MinChars = 3                    # 少于此字数不翻译（1〜50）
MaxPerMinute = 20               # 每分钟翻译次数上限（1〜120。超出的不翻译）

[Permissions]                   # 权限（v0.4b）。名单在 BepInEx\PocketRoles\Admin.txt / Moderator.txt / VIP.txt / Banlist.txt
AdminsCanChangeSettings = true  # Admin.txt 中的玩家可使用房主命令（/set /opt /show /start /cancel /autostart /welcome /rules /kick /ban /vset …）
ModeratorsCanKick = true        # Moderator.txt 中的玩家可使用 /kick 和 /ban
VipMarker = true                # 给 VIP.txt 中的玩家名字加★，加入时单独问候

[Vanilla]                       # 原版设置范围扩展（v0.4b）。设置界面的箭头和 /vset。数值会同步给原版玩家
ExtendedRanges = true           # 允许原版数值设置超出原版上下限
KillCooldownMin = 0             # 设置界面可选的最小击杀冷却（秒，0〜60。原版 10）
KillCooldownMax = 120           # 最大（秒，10〜600。原版 60）
KillCooldownStep = 2.5          # 每次点击箭头的步长（秒，0.5〜10。与原版相同为 2.5。设为 0.5 则以 0.5 秒为单位；/vset 不受步长限制）
VotingTimeMin = 0               # 投票时间最小值（秒，0〜300。原版 15。0 = 无投票）
VotingTimeMax = 600             # 投票时间最大值（秒，15〜3600。原版 300）
DiscussionTimeMax = 600         # 讨论时间最大值（秒，0〜3600。原版 120）
EmergencyCooldownMax = 120      # 紧急会议冷却最大值（秒，0〜600。原版 60）
```

## 13. 语言（日本語 / 中文 / English）

PocketRoles 发给玩家的文字（欢迎语、职业名和说明、命令回复、击杀等通知、房间剩余时间和废村的提示、对局结果）支持 **日本語（ja）、简体中文（zh）、English（en）** 三种语言。

### 房间默认语言

`[General] Language`（默认 `ja`）。可以通过设置标签页的“语言”、齿轮面板的“语言”、`/opt lang zh` 或 `/lang default zh` 更改。房主自己输入 `/lang zh` 时也会更改默认语言（发给房主的所有显示、设置标签页、齿轮面板、快捷键的确认提示都使用默认语言）。

### 每位玩家的语言

玩家可以用 `/cmd lang zh`（已注册的房间中是私密的）或 `/lang zh`，把 **发给自己的消息** 单独设置成另一种语言。欢迎语默认用三种语言送达（该玩家的语言 → 其余两种语言）；只用一种语言时（`WelcomeAllLanguages = false`）会改为附带一行三种语言的提示 `English: /cmd lang en ｜ 中文: /cmd lang zh ｜ 日本語: /cmd lang ja`（v0.4b），看不懂房间语言的人也能马上切换。

- 适用范围：欢迎语、职业通知（开始时、会议时）、命令回复、击杀 / 跳管 / 破坏相关通知、自动开始 / 延长 / 废村 / 结束会议的全员提示、测试模式提示、对局结果列表、翻译的推送等所有发给该玩家的内容（全员提示也会逐个按各自的语言组装后发送）。
- 选择按好友代码 / Puid 记住，**直到房主关闭游戏**（同一次运行中，重建房间或该玩家重新加入都会保留。只有既没有好友代码也没有 Puid 的玩家的选择会在换房间后清除）。`/lang reset` 恢复默认。
- 语言参数可以写 `en` / `english` / `英語`，`zh` / `zh-CN` / `cn` / `中文` / `简体中文` / `中国語`，`ja` / `jp` / `日本語` 等。
- 日文、中文的帮助会附带一行简短的英文（`EN: …`）。
- **语言自动识别**（v0.4b，`[Translate] AutoDetectLang = true`，设置标签页“自动识别语言”）：未使用 `/lang` 的玩家用中文或英文写了 6 个字符以上的聊天时（使用翻译服务的判断），会把该玩家的显示语言 **只自动切换一次** 为该语言，并用该语言只向本人提示“显示语言已切换为中文。输入 /cmd lang ja 可切换回去。”。房主和已经用 `/lang` 选择过的玩家不受影响。聊天翻译关闭时不会识别。
- **用三种语言发送欢迎语**（`[Chat] WelcomeAllLanguages = true`，设置标签页“用三种语言发送欢迎语”，`/opt chat.welcomeall on`。从 v0.4.1 起默认开启）：简短的欢迎语（2 行）按 该玩家的语言 → 其余两种语言 的顺序发送（2 行 × 3 种语言 = 6 条 + 翻译提示 1 条，依次送达）。此时不附带三语提示行。关闭时为该玩家语言的 2 行 + 三语提示行 1 条。

### 文本文件（可编辑）

文本从 `BepInEx\PocketRoles\lang\` 下的 `ja.json` / `zh-CN.json` / `en.json` 读取（首次启动时会写出模组内置的默认内容）。

```json
{
  "role.sheriff.name": "警长",
  "role.sheriff.desc": "可用击杀键射杀内鬼和豺狼。…",
  "welcome.1": "职业MOD房间。什么都不用装。游戏开始后你的职业会显示在自己名字上方。",
  "haison.notice": "为了防止房间超时，将开始一局游戏并立即结束。…",
  "cmd.lang.set": "语言已设为 {0}。"
}
```

- 是“键”→“文字”的扁平 JSON（UTF-8，不允许注释）。对照三个文件就能看出每个键的含义。
- `{0}` `{1}` 之类的占位符请 **原样保留**（会被替换为数字或名字）。
- 职业名用 `role.<职业键>.name`、说明用 `role.<职业键>.desc` 修改（职业键：`sheriff`、`mayor`、`snitch`、`lighter`、`speedbooster`、`bait`、`madmate`、`vampire`、`mafia`、`jester`、`opportunist`、`terrorist`、`jackal`）。设置标签页的标题、项目名是 `opt.section.*` / `opt.name.*`，齿轮面板是 `ui.gear.*`。
- 缺少键时使用模组内置的文字。JSON 损坏时会忽略该文件、回退到内置文字，并在日志中记录错误。
- 编辑后用 `/lang reload`（房主）或重启游戏生效。
- 更新后新增了键时，启动时会 **只把缺少的键** 用内置文字追加进去（自己编辑过的文字保持不变）。想获得新的默认文件，请删除文件后再启动。

职业名的指定（`/set`、`/assign`、`/cmd r`）与语言无关，英文名、日文名、中文名、缩写都可以。

### 聊天翻译（v0.4b，`[Translate]`）

自动翻译外语聊天的功能。**默认开启**，以 **并用模式**（见下文）运行。翻译由房主的电脑把文本发送到翻译服务（Google；`deepl-key.txt` 中有密钥时为 DeepL）完成，不想把文本发送到外部时，请在设置标签页“聊天”分页的“聊天翻译”或用 `/opt translate off` 关闭。

**关于隐私（请务必阅读）**：此功能开启期间，**到达房主屏幕的聊天文本（其他玩家的和自己的）会被发送到 Google（`translate.googleapis.com`）或 DeepL（`api.deepl.com` / `api-free.deepl.com`）**。只发送文本，不发送名字和房间代码。为了让玩家知情，开启期间欢迎语中会有一行“自动翻译已开启：用你的语言写即可 / Auto-translation is on / 翻訳あり”，`/h` 中也有提示。不想把文本发送到外部时，请在设置标签页“聊天翻译”或用 `/opt translate off` 关闭（以 `/` 开头的命令不会被翻译）。

| 设置 | 默认 | 内容 |
|---|---|---|
| `Enabled`（设置标签页“聊天翻译”，`/opt translate on|off`） | true | 翻译的开关 |
| `Provider`（“翻译服务”，`/opt translate.provider`） | auto | `auto` = `deepl-key.txt` 中有密钥则 DeepL，否则 Google。`google` = 无需密钥的公开接口（尽力而为，拥挤时可能失败）。`deepl` = DeepL API（没有密钥时改用 Google 并在日志中警告） |
| `TargetLang`（“翻译目标语言”） | 空 = 房间默认语言 | 房主阅读翻译的语言（ja / zh / en） |
| `ShowOnHost`（“房主屏幕显示翻译”） | true | 在房主屏幕显示 `[译] 名字: 翻译`（不发送） |
| `BroadcastToAll`（“翻译发送给所有人”） | true | 把外语聊天翻译成房主的语言 **发送给所有人**（发送者名“译”。会收到自己语言的单独翻译的玩家除外） |
| `TranslateForPlayers`（“为外语玩家翻译”） | true | 向用 `/lang` 选择了与房间默认语言不同的语言的玩家，把其他人的聊天翻译成其语言 **单独发送**（房主的中文 / 日文也会送达外语玩家） |
| `AutoDetectLang`（“自动识别语言”） | true | 见上文“语言自动识别” |
| `MinChars`（“翻译最少字数”） | 3 | 短于此的文本不翻译（1〜50） |
| `MaxPerMinute`（“每分钟翻译上限”） | 20 | 每分钟翻译次数上限（1〜120）。超出的不翻译，房主屏幕每分钟最多提示一次“已达到翻译次数限制，暂时省略翻译。” |

**使用 DeepL（设置密钥）**

1. 注册 DeepL API 账户（免费的 DeepL API Free 也可以），获取 API 密钥（形如 `xxxxxxxx-xxxx-…:fx`。Free 的密钥以 `:fx` 结尾）。
2. 用记事本创建 **`BepInEx\PocketRoles\deepl-key.txt`**，**只把密钥写在第一行** 并保存（UTF-8。空行和以 `#` 开头的行会被忽略）。
3. `Provider` 保持 `auto` 即可（有密钥时自动使用 DeepL）。游戏运行中创建的文件也会在 1 分钟内被读取。

密钥 **绝对不要写进配置文件（`jp.pocketroles.mod.cfg`）**（`/opt` 也没有密钥项）。密钥只从这个文件读取、只发送给 DeepL，不写入日志，也不包含在启动器的报告 zip 中（万一混入日志等文件，生成报告 zip 时会替换为 `<api-key-masked>`）。DeepL 失败时（密钥无效、超出额度等）改用 Google，并在日志中警告一次。

**并用模式（默认：`BroadcastToAll = true` + `TranslateForPlayers = true`）的运作**（以房主为日语的情况为例）

- 中国玩家用中文发言 → **日文翻译发给所有人**（发送者名“译”。发言者本人也会收到，因此知道已被翻译）。中文翻译与原文语言相同，不发送。
- 房主用日文发言 → **只有选择了中文的玩家会单独收到中文翻译**（发给所有人的只有房主语言的翻译）。
- 英语玩家用英文发言、且房间里有中国玩家 → 中国玩家 **只收到一条中文翻译**（不在日文广播的对象里），其他人收到日文翻译。同一个人不会收到两份。
- 少于 `MinChars`（3）个字符或只有表情 / 数字的文本不翻译。未注册（便利房）的房间只发广播，不发单独翻译。

**工作方式**

- 到达房主屏幕的聊天中，非命令（`/`）、3 个字符以上（`MinChars`）、包含 2 个以上字母 / 文字（排除只有表情和数字的）、300 字以内的文本会在后台翻译。聊天的显示不会被阻塞。
- 翻译目标是“房主的语言”（自己的发言除外），以及 `TranslateForPlayers` 开启时“各外语玩家的语言”。原文已被判断为该语言时不显示任何内容。
- 相同文本缓存 10 分钟。无法连接翻译服务时，每个房间在房主屏幕上只提示一次“无法连接翻译服务（…）”。
- 玩家收到的翻译（`TranslateForPlayers` / `BroadcastToAll`）与其他模组消息相同（发送者名“译”，每条 100 字，依次送达）。

## 14. 加入时的欢迎语与规则行

玩家进入房间 3 秒后，会收到只发给本人的欢迎语（`WelcomeMessage = true` 时。多人同时加入也会依次发送）。从 v0.4.1 起，欢迎语是面向新手的 **简短 2 行**，默认按 该玩家的语言 → 其余两种语言 的顺序用三种语言送达（`WelcomeAllLanguages = true`）。每条不超过 100 个字符，每种语言最多 4 条（附带设置行时 5 条。翻译提示行和三语提示行各 +1 条，VIP 行 +1 条）。

**默认欢迎语**（默认设置、中文玩家的情况。之后还会跟着日文版、英文版的同样 2 行）：

```
职业MOD房间。什么都不用装。游戏开始后你的职业会显示在自己名字上方。
职业说明：会议聊天中输入 /cmd r 职业名（例 /cmd r sheriff）。全部职业 /cmd r，帮助 /cmd h
（日文版的 2 行）
（英文版的 2 行）
自动翻译已开启：用你的语言写即可 / Auto-translation is on / 翻訳あり
```

- 第 1 行说明这是模组房间（什么都不用装，职业显示在自己名字上方），第 2 行说明如何查看职业说明。两行都不超过 100 个字符，各自一条消息送达。
- **规则行** 只在用 `/rules <文字>` 设置了自己的规则时才作为第 3 行加入（v0.4.1。默认的“无规则”文字不再出现在欢迎语中）。
- 最后一行是 **翻译提示**（仅聊天翻译开启时。[第 13 章](#13-语言日本語--中文--english)）。用三种语言发送时也只附带一次。
- 启用的职业列表和设置的罗列（`警长 x1 击杀CD30秒 可杀狂粉 / … / 语言=zh MOD注册=on 欢迎语=on`）不再出现在欢迎语中（v0.4.1）。玩家可以用 `/cmd s`（本房间的设置）和 `/cmd r`（职业列表）查看。`WelcomeIncludeSettings = true`（`/welcome settings on`，设置标签页“欢迎语包含设置”。默认关闭）时会像以前一样在末尾附上设置行（与 `/show` 相同。自动重开房 / 自动公开、自动开始 / 游戏主持开启时也附带相应的行）。
- 列在 `VIP.txt` 中的玩家最后还会收到“★ 欢迎 VIP ○○！感谢一直以来的支持。”（[第 11 章](#11-命令一览)）。
- `WelcomeAllLanguages = false` 时，只发送该玩家语言的 2 行，并附带 **三语切换提示** `English: /cmd lang en ｜ 中文: /cmd lang zh ｜ 日本語: /cmd lang ja`（仅玩家可以使用命令时。关闭注册的房间中为 `/lang en` 的形式）（v0.4b）。
- 禁用玩家命令时（`PlayerCommands = false`），第 2 行变为“本房间已禁用聊天命令（房主设置）。”，也不附带三语提示行。

### 规则行（`/rules`）

| 命令 | 内容 |
|---|---|
| `/rules` / `/rules show` | 当前的规则行和用法 |
| `/rules <文字>` | 设置规则（最多 200 个字符。`\n` 换行）。保存到 `[Chat] RulesMode = custom`、`RulesText` |
| `/rules none` | 恢复为默认（“本房间没有特别规则…”）（`RulesMode = none`） |

例：`/rules 新手欢迎！\n禁止辱骂和爆料。` → 插入欢迎语的第 3 行（`/welcome show` 可预览）。默认的规则文字会按语言翻译，自己写的文字保持原样。

### 使用自己的文字（`/welcome`）

用 `/welcome <文字>` 替换正文（第 2 行以后；最多 320 个字符）。第一行“职业MOD房间。什么都不用装。…”是模组房间的说明（模组政策要求的通知），**一定会附加，无法去掉**。

- `\n`（反斜杠和 n 两个字符）表示换行。
- 占位符：`{rules}` = 规则行，`{roles}` = 启用的职业列表，`{settings}` = 当前设置（与 `/show` 相同），`{help}` = 帮助和更改语言的一行提示，`{version}` = 模组版本。
- 即使不写 `{settings}`，只要“欢迎语包含设置”为开（默认关闭），设置也会附加在末尾。即使不写 `{rules}`，只要用 `/rules` 设置了规则，规则行也会附加在末尾（默认的“无规则”文字只会出现在写了 `{rules}` 的位置）。

示例：

```
/welcome 欢迎！新手也欢迎。\n今天的职业：{roles}\n{rules}\n{help}
```

`/welcome show` 在房主画面上预览，`/welcome reset` 恢复默认。只输入 `/welcome` 会显示当前状态和用法。配置文件中的 `[Chat] WelcomeText` 保存同样的文字（带 `\n`）。

欢迎语按接收者的语言组装（默认文字和占位符部分会翻译，自己写的正文保持原样）。

## 15. 自动重建房间与自动公开

### 自动重建房间（`/rehost on`，`[Lobby] AutoRehost`，齿轮面板“自动重开房”）

开房期间被服务器 **意外断开** 时（服务器错误、超时、反作弊踢出等），会自动重新创建房间。

- 自己退出房间，或因封禁、制裁、重复连接等原因被断开时不会重建。
- 断开 5 秒后（连续失败时延长为 10 秒、20 秒，最长 30 秒；服务器拥挤类原因为 30 秒），等客户端回到标题画面后以相同的游戏模式创建房间。断线对话框会自动关闭。
- 连续失败 `RehostMaxAttempts`（默认 3）次后放弃。房间持续 60 秒以上则计数重置。
- 等待期间如果自己手动创建或加入了房间，重建会被取消。
- 原房间是公开的话，新房间也会恢复为公开。
- 新房间创建后，房主的聊天中会显示“断线后已自动重新创建房间。新房间代码：XXXXXX”。**房间代码会改变**，请重新告诉参与者（用 `/announce` 复制后重新贴到 Discord 等；用引导房的话也改一下它的名字，[第 25 章](#25-便利房关闭注册与引导房)）。应对房间超时请使用废村（[第 16 章](#16-房间剩余时间自动开始与废村)），这样代码不会变。
- 登录状态（EOS）失效时不会重建，交由游戏的登录界面处理。

### 延迟过高时询问是否重建房间（`[Lobby] MaxHostPing`，`/opt maxping <ms>`）

即使在官方亚洲区域，分配到的服务器也可能是 8〜10 ms（东京）或 70 ms 以上（远处的服务器）。把 `MaxHostPing` 设为大于 0（例如 `/opt maxping 40`）后，创建房间后的 5 秒内延迟一直高于该值且还没有人加入时，房主屏幕会弹出 **“延迟较高（N ms）。要重新创建房间吗？（仅在无人加入时）”** 对话框（是 / 否）。也可以在聊天里用 `/rehost yes` / `/rehost no` 回答。

- “是”会用相同设置重新创建房间（代码会变；最多连续 3 次）。“否”则本房间不再询问。有人加入后就不会询问。
- **默认关闭（0）**：短时间内反复重建房间会被视为故意断线（ban points），暂时无法创建房间（[3.4](#34-关于封禁与踢出)）。只在必要时使用，每次询问最多重建一次。

### 自动公开（`/public on`，`[Lobby] AutoPublic`，齿轮面板“自动公开”）

创建（重建）房间 `AutoPublicDelay` 秒后（默认 3 秒，0〜60）自动切换为“公开”。房主的聊天中会显示“房间已设为公开。”

- `/public now` 可以立即设为公开（仅在线房间中）。
- 游戏版本不一致（[第 24 章](#24-游戏版本检查)）期间不会自动公开。
- 已注册的房间即使设为公开也 **不会显示在列表中**（[3.2](#32-已注册的房间不会出现在公开房间列表中)）。想出现在列表里时，请用关闭注册的“便利房”（无职业）加引导房（[第 25 章](#25-便利房关闭注册与引导房)）。

只输入 `/rehost`、`/public` 会显示当前状态。也可以在设置标签页的“大厅”分组中更改。

## 16. 房间剩余时间、自动开始与废村

官方服务器的房间有寿命（约 10 分钟），超时后房间会关闭。v0.4 会一直显示剩余时间，并提供自动开始和超时对策。**这些功能只在在线房间中** 工作（本地房间没有时间限制）。

### 16.1 剩余时间的显示

- 游戏本身不保存房间的剩余时间，所以模组在 **进入房间时按 597 秒** 估算，并在收到服务器的剩余时间通知（延长询问）时替换为真实值。延长确定后加上延长的时间（通常 5 分钟）。显示的是“约”值。
- 房主屏幕左上角（ping 显示下方）显示 `房间剩余 mm:ss`（剩余 120 秒以内为黄色，60 秒以内为红色）。进入房间 1 秒后也会显示原版的计时器。
- 任何人都可以用 `/time`（`/cmd time`）查询剩余时间。房主还会看到“超时时的动作: extend  自动开始: 开启（10人时5秒后）  /start 立即开始, /haison 废村重置计时”。
- 剩余 120 秒时向所有人提示“房间剩余时间约120秒。”（`TimerWarnAt` 小于 120 时。60 秒的提示只在 `TimerWarnAt` 小于 60 时发送，默认情况下改为发送 16.3 的警告）。

### 16.2 自动开始（`[Lobby] AutoStart`，`/autostart`）

| 设置 | 默认 | 内容 |
|---|---|---|
| `AutoStart` | false | 自动开始的开关（`/autostart on|off`、设置标签页“自动开始”、齿轮面板“自动开始”） |
| `AutoStartPlayers` | 10（4〜15） | 凑齐此人数后开始（`/autostart <人数>` 设置并开启） |
| `AutoStartCountdown` | 5（1〜30） | 倒计时秒数（`/start` 也使用） |

规则 1（人数凑齐时）：

1. 在大厅中开启自动开始、没有任何开始流程时，人数达到 `AutoStartPlayers` 后向所有人提示“已凑齐10人。5秒后开始。”并进入开始倒计时（与原版的“Game starting in 5”相同。房主的 Start 按钮变为“取消”按钮）。
2. 倒计时期间人数减少到 `AutoStartPlayers` 以下时自动取消，并提示“人数少于10人，已中止自动开始。”人数回来后会再次倒计时。
3. 房主用取消按钮 / F9 / `/cancel` 取消后，要等人数先减少到 `AutoStartPlayers` 以下再次凑齐才会重新开始（避免立即重启）。

规则 2（剩余时间不多时，16.3）中若人数已凑齐则 5 秒后开始。

`/start` 不论是否自动开始，都会 **立即**（`AutoStartCountdown` 秒后）开始。1 个人也能开始（测试时很方便）。自动开始、`/start`、废村、测试模式任一生效期间，开始所需的最低人数为 1。

### 16.3 超时对策（`[Lobby] TimerMode`，`TimerWarnAt`，`ExtendNoticeDelay`）

剩余时间降到 `TimerWarnAt`（默认 60 秒）以下且没有开始流程时，执行一次以下动作。

| 情况 | 动作 |
|---|---|
| 自动开始已开启且人数已凑齐 | “房间剩余时间不多，5秒后开始。”→ 5 秒后开始 |
| `TimerMode = extend`（默认） | “房间剩余时间不多，5秒后延长时间（房间保持不变）。”→ `ExtendNoticeDelay` 秒后，如果服务器发来了延长询问则 **接受延长**（“将延长房间时间（房间保持不变）”→ 确认后“已延长房间时间（房间保持不变）。剩余约mm:ss”），如果没有询问 / 8 秒内未确认则 **废村** |
| `TimerMode = haison` | “房间剩余时间不多，5秒后刷新房间（开始一局并立即结束）。房间保持不变。”→ `ExtendNoticeDelay` 秒后废村 |
| `TimerMode = notify` | 只提示“房间剩余时间约60秒。房间即将关闭。”（不做任何事） |

- 延长 / 废村 **不会因为人数减少而取消**。从提示到执行之间如果房主按了 Start 则正常开始。
- 可延长的次数由服务器决定（询问会在房间快结束时发给房主。模组做的相当于自动在原版的延长弹窗中点“是”）。延长后剩余时间再次降到 `TimerWarnAt` 以下时会再次执行。
- `TimerMode` 可通过设置标签页“大厅倒计时动作”、齿轮面板“大厅倒计时动作：延长 / 废村 / 仅通知”、`/opt lobby.timermode` 更改。

### 16.4 废村（`/haison`、`/廃村`、F7 ×2）

“废村”是为了防止房间超时而 **开始一局游戏并立即结束，让所有人回到同一房间（同一房间代码）** 的操作（与 SuperNewRoles 等相同的思路）。回到大厅后房间的寿命会重新计算。

在大厅执行时的流程：

1. 向所有人提示“为了防止房间超时，将开始一局游戏并立即结束。房间和房间代码保持不变，请不要退出。”（各自的语言）。
2. 1 秒后进入 5 秒倒计时 → 游戏开始。这局一次性对局 **不会分配职业**（只有原版职业）。倒计时期间用取消按钮 / F9 / `/cancel` 取消时，废村也会中止。
3. 开场动画结束后（没有开场动画时为开始 12 秒后）立即结束游戏（按原版“内鬼断线”的方式结束。没有胜负和结果列表）。
4. 所有人回到大厅，并提示“房间已刷新，可以继续游戏。”

- 已经有普通的倒计时在进行时不做任何事（那局结束后房间寿命会重新计算）。40 秒后游戏仍未开始则放弃。
- **游戏进行中** 执行 `/haison` 或 F7 ×2 时，向所有人提示“房主结束了本局游戏（废村）”并立即结束本局，回到同一房间（无胜负、无结果列表）。这与测试模式的 `/end`（按船员获胜处理）不同。
- 结算画面进行中无法执行（“现在无法执行（请在结算画面结束后再试）。”）。仅在线房间。

## 17. 快捷键与取消按钮

### 取消按钮

在房主的画面上，开始倒计时期间 Start 按钮的位置会出现 **“取消”按钮**（原版 Start、自动开始、`/start`、废村的倒计时都适用）。点击后执行原版的取消处理，所有人的“Game starting in …”显示消失。已经进入开始流程后（倒计时归零后）无法取消。

### 快捷键（`[Hotkeys]`）

仅房主可用，且只在聊天栏未打开 / 未输入时生效。`[Hotkeys] Enabled = false`（设置标签页“启用快捷键”、齿轮面板“启用快捷键”）可全部禁用。

| 按键（默认） | 动作 | 按法 |
|---|---|---|
| **F7** | 大厅中为废村（刷新房间），游戏中为立即结束本局并回到同一房间（[16.4](#164-废村haison廃村f7-2)） | **3 秒内按两次**。第一次按下时显示“在 3 秒内再按一次 F7 即可废村（刷新房间）”（画面上方的提示和房主本地的聊天中都会显示） |
| **F8** | 截止会议投票（[第 18 章](#18-强制结束会议)） | **3 秒内按两次**。非投票中（讨论 / 投票）时不做任何事 |
| **F9** 或 **Esc** | 取消开始倒计时 | 按一次。仅倒计时期间（Esc 只在倒计时期间响应）。F9 在聊天输入中也有效（v0.4c） |

- 按键可通过 `[Hotkeys] Haison / EndMeeting / CancelStart` 更改（设置标签页中从 F1〜F12 选择，`/opt hotkeys.haison F5` 这样的写法可以使用任何 UnityEngine.KeyCode 名称）。字母键容易与聊天和房间代码输入冲突，推荐使用 F 键。
- 模组关闭时（`/mod off`、版本不匹配等）F7 / F8 不起作用。F9 / Esc 的取消与模组开关无关。

## 18. 强制结束会议

会议拖得太久时，房主可以截止投票继续游戏。

| 操作 | 动作 |
|---|---|
| `/endmeeting`（`/em`）、F8 ×2 | 向所有人提示“房主结束了会议”并截止投票。**与投票时间用完时的处理相同**：尚未投票的人按“未投票”（不计票）统计，正常进入结果 → 放逐画面。市长的多票也会生效。仅讨论中 / 投票中（结果显示中会回复“投票已经结束。”） |
| `/results` | 缩短投票结果画面（5 秒），立即进入放逐画面。仅结果显示中（投票中会回复“仍在投票中。可用 /endmeeting 结束投票。”） |

玩家一方看到的是与原版投票时间用完时相同的流程（除了聊天提示外一切照常）。会议剩余时间的显示由各客户端自己保存，无法缩短（会被截止覆盖）。

## 19. 自动选择区域（最快服务器）

设为 `[Lobby] AutoRegion = true`（设置标签页“自动选择最快区域”、齿轮面板“自动区域”、`/opt lobby.autoregion on`）后，**打开在线菜单时**（尚未连接服务器时）会测量官方 3 个区域（North America / Europe / Asia）的响应时间，并自动切换到最快的区域。

- 测量方法：向各区域的匹配服务器（`https://matchmaker[-eu|-as].among.us`）发送 3 次 HTTPS HEAD 请求（外加 1 次预热，超时 3 秒），按中位数比较（与 SuperNewRoles 相同的方式）。结果缓存 10 分钟。
- 当前区域与最快区域不同时用 `SetRegion` 切换（会保存到游戏的区域设置中，因此手动选择的区域会被覆盖）。连接中不切换，会在下次开房前切换。
- 结果会在下一次开房的大厅聊天中（仅房主）显示一次：

  ```
  自动选择区域:
  North America: 180 ms
  Europe: 250 ms
  Asia: 45 ms
  区域已切换为 Asia（North America → Asia）
  ```

- `/region`（房主）可以随时查看“当前区域”“延迟（中位数）”表以及“自动选择最快区域: 开/关”。自动选择关闭期间不会测量，表格会显示“尚未测量延迟（打开在线菜单时会测量）。”
- 注意：测量的是到匹配服务器（经 CDN）的 HTTPS 响应时间，可能与实际游戏服务器的 ping 不同。

## 20. 游戏主持（观战 / 主持）

设为 `[General] GameMaster = true`（设置标签页“游戏主持”、齿轮面板“游戏主持”、`/opt gm on`）后，从下一局起房主 **不作为玩家参与**，而是观战 / 主持（与 AUR / EHR 的 GM 模式思路相同）。

- 房主不参与职业抽选（特殊职业和原版内鬼名额都不参与）。用 `/assign` 给房主指定职业也会被忽略。
- 房主的开场动画显示“游戏主持”“观战/主持（不参与游戏）”（仅房主画面）。
- 开场动画结束后房主立即 **按死亡处理**（向所有人发送与放逐相同的处理，成为船员幽灵），任务也会清空。向所有人提示“房主是游戏主持（观战/主持），不参与游戏。”
- 房主的画面上聊天和地图按钮仍可使用。不会成为守护天使。
- 胜负判定不计入房主（按死亡者处理）。
- 参与者少于 2 人的对局（只有房主）和废村的一次性对局不适用。

注意：死亡状态的房主输入的 **普通聊天**，按原版规则存活者看不到（只有死者能看到）。模组的通知（职业通知、命令回复、`/endmeeting` 等提示）会让房主在通信上短暂视为“存活”再发送，所以仍会送达所有人（未注册的便利房根本不发送私密消息）。作为主持想对所有人说话时，请使用命令提示（例如 `/haison`、`/endmeeting`）或会议。

## 21. 镜像 Skeld（Dleks）

Among Us 的所有客户端都内置了左右镜像的 Skeld“Dleks（dlekS ehT）”，原本是愚人节地图。`[Lobby] EnableDleks = true`（默认，设置标签页“提供镜像 Skeld(Dleks)”、`/opt lobby.dleks on|off`）期间，房主的地图选择（创建房间画面和房间内的地图选择）中会在第 4 位（Polus 和 Airship 之间）新增 **左右镜像的 Skeld 图标**。设置列表的地图名中会显示为第二个“The Skeld”。

- 选择后，房间设置在网络上仍按 **The Skeld** 发送（原版客户端在大厅中显示“The Skeld”）。进入开始倒计时时地图切换为 Dleks，由房主加载镜像 Skeld 的飞船并分发给所有人。原版玩家也能 **直接游玩镜像 Skeld**（地图数据所有人都有）。
- 取消倒计时后房间设置恢复原样。对局结束回到大厅后选择仍保留（重建房间则清除）。
- 不会出现在公开房间的筛选列表中。镜像的 Airship 等并不存在，因此无法提供。
- 与 EHR / AUR 的 DleksPatch 相同的方式。

## 22. 外观自定义（仅房主屏幕）

这是 v0.3 的功能。在 `BepInEx\PocketRoles\` 中放入图片或音乐后，**只有房主（你）的屏幕** 外观会改变。**不会向玩家发送任何数据，玩家一方仍是原版**（即使替换了帽子，其他人看到的仍是那个人原本戴的帽子）。模组在同一文件夹中写出的 `README.txt`（日文）也有相同说明。

### 文件夹结构（首次启动时自动创建）

```
<游戏>\BepInEx\PocketRoles\
  hats\<ProductId>.png            帽子的主图。可选：<ProductId>_back.png / _left.png / _left_back.png / _climb.png / _floor.png
  visors\<ProductId>.png          面罩。可选：_left.png / _climb.png / _floor.png
  nameplates\<ProductId>.png      会议画面的名牌
  music\*.wav | *.ogg             大厅 BGM（找到的第一个文件，或 LobbyMusicFile 指定的文件）
  images\lobbypaint.png           大厅墙画（可选）
  images\dropship.png             飞船装饰（可选）
  images\menu.png                 主菜单背景（可选）
  images\cursor.png               鼠标光标（可选，建议 64×64 以下）
  README.txt                      模组写出的说明（编辑后下次会被覆盖）
```

### 如何查看 ID（文件名）

房主在大厅的聊天中输入 `/cos ids`，所有玩家的帽子、面罩、名牌、皮肤、宠物的 ProductId 会显示在房主画面（和日志）中。

```
Taro: hat=hat_pk05_Cheese visor=visor_Cat plate=nameplate_Bavarian skin=- pet=-
```

例：`hat_pk05_Cheese` → `hats\hat_pk05_Cheese.png`，`visor_Cat` → `visors\visor_Cat.png`，`nameplate_Bavarian` → `nameplates\nameplate_Bavarian.png`。

- 替换会应用于房主屏幕上 **无论谁戴着** 的该 ID 的帽子、面罩、名牌（包括大厅、游戏中、会议画面、商店预览）。
- 皮肤和宠物因为是动画，不在替换范围内（只能查看 ID）。

### 图片技巧

- 按 **与原图相同的像素尺寸** 绘制，位置和大小会完全一致。尺寸不同时帽子、面罩会按默认基准点（与 SNR / TOR 相同）显示。
- 会随玩家颜色变化的帽子（adaptive），图片中的 **纯红 (255,0,0) 替换为身体颜色，绿 (0,255,0) 替换为阴影，蓝 (0,0,255) 替换为面罩颜色**（这是从其他模组的惯例推断的规则，请先试一个）。不变色的帽子请用正常颜色绘制。
- 推荐透明 PNG。
- `images\lobbypaint.png` 按 290 px/unit、`dropship.png` 按 60 px/unit、`menu.png` 按 150 px/unit（1920×1080 左右）显示。光标的热点是左上角。

### 大厅 BGM

- 格式：**WAV**（8 / 16 / 24 bit PCM、32 bit float、单声道 / 立体声）或 **OGG Vorbis**。**不支持 MP3**。
- `[Cosmetics] LobbyMusic`：`custom`（默认。`music` 文件夹中有文件则播放，没有则原版）| `vanilla`（游戏主题曲）| `mute`（无大厅音乐）。用 `/cos music custom|vanilla|mute`、设置标签页“大厅音乐”、齿轮面板“大厅音乐”切换。
- `LobbyMusicFile` 指定文件名（空 = 找到的第一个文件）。`LobbyMusicVolume`（0〜1，默认 0.07）是自定义曲目的音量，原版主题曲约为 0.07，所以经过正常音量归一化的曲目请设小一些。游戏的音乐滑块也有效。
- 玩家听到的是各自的原版主题曲。

### 其他

- `[Cosmetics] Enabled = false`（设置标签页“自定义外观”、齿轮面板“外观(v0.3)”）全部关闭。`LobbyPaint` `Dropship` `MenuBackground` `Cursor` 可单独关闭。
- 更换文件后执行 `/cos reload`（清除图片、音乐缓存并重新应用）。
- 画面上的对象名（墙、飞船、菜单背景）可能随游戏更新而改变。找不到时日志中只警告一次，并跳过该装饰。

## 23. 测试模式（用一台手机验证）

正式开房前，可以用 **PC（房主）＋手机（原版）两台设备** 确认原版玩家看到的效果。测试模式下：

- **1 个人也能按开始键**（把 `MinPlayers` 设为 1）。
- **胜负判定暂停**。人数减少、任务完成都不会结束游戏。只有 `/end`（按船员获胜处理）、F7 ×2 / `/haison`（无胜负）和反应堆等紧急破坏倒计时耗尽才会结束。
- 可用 `/assign` 指定下一局的职业。
- 状态 **只在本房间期间有效**，不会保存到配置文件。重建房间（或进入其他房间）后自动关闭，职业指定也会清除。
- 开关的切换及其通知所有人都能看到（“测试模式 开启：可单人开始，游戏不会自动结束（用 /end 结束）。”）。

### 步骤

1. 在 PC 上带模组启动，在线创建房间（经典模式）。如果开启了自动选择区域，大厅的聊天中会显示测量结果。
2. 用手机（原版 Among Us）输入房间代码加入。确认手机收到欢迎语（含规则行）。也可以在手机上输入 `/cmd lang zh` 或 `/cmd time`，确认回复使用该语言。
3. 在房主的聊天中输入 `/test on`。
4. 指定想测试的职业。可以用名字，也可以用玩家编号（`/assign show` 或按颜色顺序的编号）。名字支持部分匹配（能唯一确定一人时）。

   ```
   /assign <手机的名字> sheriff       ← 让手机一方成为警长
   /assign <自己的名字> vampire        ← 让自己成为吸血鬼（即使是普通船员也会按内鬼处理）
   /assign show                         ← 确认指定
   ```

   职业可以不受正常抽选名额限制地指定。把内鬼名额的职业（吸血鬼、黑手党、女巫、刺客、邪恶鹰眼、邪恶猫又、连环杀手、武士）指定给船员时，该玩家会以内鬼身份开始（恋人保持原来的阵营：指定给内鬼就成为内鬼恋人）。指定在一局游戏中消耗掉（下一局需要重新指定）。`/test off` 会清除所有指定，所以要测试正式的胜负判定时，请按 `/test off` → `/assign` → `/start` 的顺序。
5. 开始游戏。用 Start 按钮或 `/start` 都可以（出现“等待同步”时几秒后再按一次。测试模式下游戏本体的“4 人可以游玩，但…”弹窗会自动确认）。倒计时期间试试 **取消按钮 / F9 / `/cancel`**，可以确认手机上的“Game starting in …”也会消失。
6. 在手机画面上确认：开场动画（警长会显示“内鬼”）、名字上方的职业名、开始约 8 秒后的聊天（警长会带“※游戏本体显示你是“内鬼”…，但你的真正职业是警长。”一行）、击杀键（警长误杀等）、`/cmd n` 的回复、会议画面中的名字、会议中的职业说明、跳管和破坏被拒绝等。
7. 召开会议后按 **F8 ×2**（或 `/endmeeting`）→ 确认手机上投票也被截止并进入结果画面，`/results` 会缩短结果画面。
8. 用 `/end` 结束游戏。确认结束画面（手机上只有 Victory / Defeat）和回到房间后的结果列表。
9. 换其他职业重复，或用 `/test off` 恢复普通模式。

测试 v0.4 功能时：

- **废村**：在大厅输入 `/haison`（或 F7 ×2）→ 提示 → 5 秒倒计时 → 开场动画 → 立即结束 → 回到同一代码的房间并显示“房间已刷新”。游戏中按 F7 ×2 → 立即结束并回到同一房间。
- **房间计时**：`/time` 的显示、左上角的 `房间剩余`，直接等待 9 分钟左右，剩余 60 秒时会出现延长 / 废村的提示并执行（日志中也有记录）。
- **镜像 Skeld**：在地图选择中选镜像 Skeld，手机的房间设置显示“The Skeld”，但开始后是左右镜像的地图。
- **游戏主持**：`/opt gm on` → 开始后房主的开场动画变为“游戏主持”，开场动画后房主按死亡处理，并且手机收到“房主是游戏主持”的提示（2 人以上开始）。
- **齿轮面板**：设置菜单 →“PocketRoles 设置”，确认切换与设置标签页联动。

测试 v0.4b 功能时（PC + 手机两台设备，约 10 分钟）：

1. **标题画面面板**：PC 主菜单右侧出现 PocketRoles 面板（图标、`v0.5.0 / Among Us 2026.8.18`、GitHub 行），点击 GitHub 行会打开浏览器。打开在线菜单时隐藏，返回后重新显示。
2. **设置标签页**：房间里的笔记本电脑中“PocketRoles”在最上方，点“原版设置”会展开 3 个原版按钮。职业 / 房间 / 聊天 / 外观 / 房主工具 的分页切换，鼠标悬停在“?”上时左侧说明栏显示说明。
3. **欢迎语**：手机收到的欢迎语为 2 行 × 3 种语言（该玩家的语言 → 其余两种语言），最后只附带一次“自动翻译已开启…”行，并且没有设置的罗列（用 `/cmd s` 显示）。
4. **翻译**：手机 **用英文** 发送 `Hello, can I be sheriff?` 之类的消息 → PC 屏幕上出现 `[译] <名字>: …` 的中文翻译。手机收到“Display language switched to English. Type /cmd lang zh to switch back.”，此后发给手机的模组消息变为英文（语言自动识别）。然后 PC 用中文发言 → 手机收到 `[Tr] <房主名>: …` 的英文翻译（为外语玩家翻译）。用 `/cmd lang zh` 可以切换回来。
5. **VIP**：PC 输入 `/vip add <手机的名字>` → `BepInEx\PocketRoles\VIP.txt` 多出一行。手机退出再进入后，欢迎语中带“★ 欢迎 VIP …”，开始游戏后手机的名字开头带 ★（所有人的画面）。
6. **管理员**：PC 输入 `/admin add <手机的名字>` → 手机的 `/cmd h` 末尾显示“你的权限：管理员”，`/cmd set sheriff 2` 和 `/cmd show` 可以执行（PC 的聊天中也会显示设置更改）。`/cmd test on` 会得到“仅限房主。”。用 `/admin remove <名字>` 恢复。
7. **版主 / 踢出**：`/mod add <手机的名字>` → 手机输入 `/cmd kick <PC 的名字>` 会得到“房主不能被踢出。”。PC 输入 `/kick <手机的名字>` 后手机退出（`/ban` 则重新加入时会立即被踢，`/ban remove <名字>` 解除）。
8. **原版设置范围扩展**：在 PC 的设置界面“游戏设置”中把击杀冷却的箭头调到 10 秒以下（例如 5 秒）→ 手机的房间设置列表也显示“5 秒”。`/vset vote 0`、`/vset short 12` 同样会反映。开始游戏后击杀冷却确实变短。测试完后改回正常值。
9. **报告 zip**：启动器的“生成报告 zip”→ 桌面生成 zip，其中有 `LogOutput.log` `jp.pocketroles.mod.cfg` `system.txt` 等，并且 **没有** `deepl-key.txt`。

只有房主一个人也能开始，所以只想确认房主自己的职业显示和设置是否生效时，不用手机也可以。

`/assign` 在测试模式关闭时也能使用（此时人数和胜负判定按正常规则）。在正式对局中想给特定玩家指定职业时也可以用，但请注意公平性（`/assign show` 可查看）。

## 24. 游戏版本检查

模组针对 Among Us **2026.8.18** 构建。启动时和标题画面会比较实际的游戏版本（`Application.version`），不一致时：

- 模组 **自动停用**（不分配职业、不进行通信，可以当原版玩）。
- 屏幕左上角的显示会附加红字 `(version mismatch)`。
- 创建房间时房主的聊天中会显示“PocketRoles 适用于 Among Us 2026.8.18（当前 X.X.X）。模组已禁用。可在配置中设置 IgnoreVersionMismatch=true 强制启用。”
- 日志中也会有警告。

游戏更新后，请按 [第 6 章](#6-启动器与更新) 的步骤更新模组副本并重新构建 PocketRoles。

如果一定要尝试，可以用 `[General] IgnoreVersionMismatch = true`（`/opt general.ignoreversion on`，设置标签页中的“忽略版本不匹配”）强制启用（风险自负。API 变化时游戏中可能报错或被踢出）。此状态下 `/show` 和欢迎语中会显示“注意：正在忽略游戏版本不匹配运行”，并且不会自动公开。

Harmony 补丁应用失败时（游戏内部变化较大时）模组也会自动停用（`LogOutput.log` 中会有 `PatchAll failed`）。

## 25. 便利房（关闭注册）与引导房

### 25.1 两种房间

| | 职业房（注册开启，默认） | 便利房（关闭注册） |
|---|---|---|
| 创建方法 | 照常创建房间 | 先 `/opt register off` 再创建房间 |
| 公开列表 | 不显示 | 显示 |
| 职业 | 26 种职业可用 | **不分配**（只有原版职业） |
| 发给玩家的私密消息（职业通知、欢迎语、`/cmd` 回复） | 送达（`/cmd …` 只有房主可见） | **不发送**（服务器会把私密消息视为作弊并断开房主。实机确认） |
| 聊天翻译 | 并用（广播 + 单独翻译） | 仅广播 |
| 房主工具（剩余时间、自动开始、废村、结束会议、取消、快捷键、外观） | 可用 | 可用 |
| 屏幕左上角显示（`/code on` 时） | `职业房 ABCDEF` | `便利房 ABCDEF`（`/move <代码>` 设置后下方显示 `职业→代码`） |

创建关闭注册的房间时，房主的聊天中会显示“未注册（便利房）的房间：本局按原版进行，没有自定义职业；职业需要已注册（开启 MOD 房间注册）的房间。”切换从下一个创建的房间起生效，`/opt register on` 可以恢复。

### 25.2 引导房（想招路人时：一部副手机）

职业房不会出现在公开列表里，平时把房间代码贴到 **Discord 服务器、微信・QQ 群，或直接告诉朋友** 即可（`/announce` 复制后直接粘贴）。没有社群、想从公开列表招路人时，用 **副手机（或另一台 PC）开一个原版公开房，把职业房的代码写在名字和聊天里**（引导房）来招人。这是唯一能从公开列表把人引进来的入口。玩家在引导房看到代码后，再加入职业房。

1. 在 PC 上创建职业房，输入 `/announce`（`/guide`）。房间代码会复制到剪贴板，聊天中显示步骤：
   ```
   【引导房的做法（副手机）】
   ①在副手机上把名字改为“职业→QWERTY”
   ②用原版创建一个公开房间（无模组）
   ③在聊天里写“有职业的房间是 QWERTY”
   ④代码变了（重开房间、废村后）就改名字；/announce 可再次复制
   ```
2. 在副手机的 Among Us 里把名字改为 `职业→QWERTY`（名字最多 12 个字符，代码 6 个字母，放得下）。
3. 用副手机创建 **公开** 房间（无模组，游戏设置随意）。在聊天里写“有职业的房间是 QWERTY，输入代码来玩吧”。引导房放着不管也没关系（超时后再重建）。
4. 有人来了就在 PC 的职业房正常游玩。**废村（F7）不会改变代码。** 自动重建或重建导致代码变化时，再次 `/announce` 复制并改手机的名字。

- 房间左上角的大字代码默认关闭，用 `/code on` 显示（`/code off` 隐藏。`[Guide] ShowCodeOverlay`，设置标签页“大字显示房间代码”）。显示期间，打开设置界面（房间电脑）时和对局中也会自动隐藏。
- 齿轮菜单“PocketRoles 设置”面板的下方也有同样的提示。
- 副手机请保持 Among Us 在前台（切换到其他应用可能导致房间掉线）。

### 25.3 从便利房引导到职业房（`/move`）

反过来的用法：先在公开列表里的便利房（关闭注册）聚人，再让大家转到职业房。

| 命令 | 内容 |
|---|---|
| `/move` | 用 日本語 / 中文 / English 告诉所有人“有职业的房间代码显示在引导房房主的名字上” |
| `/move QWERTY` | 把代码保存到 `[Guide] RoleRoomCode`，并用三种语言告诉所有人“有职业的房间是 QWERTY，请输入代码加入”。屏幕左上角也会显示 `职业→QWERTY` |
| `/move cancel` | 取消预定的重建（通知所有人） |
| `/announce` | 在便利房里复制用 `/move <代码>` 设置的职业房代码 |

- 设为 `[Guide] AutoRecreateRegistered = true`（设置标签页“/move 后重建为注册房”，`/opt guide.autoreg on`）后，`/move` 的 30 秒后 **本房间会重建为注册房间**（“30 秒后本房间将重建为有职业的房间，请用新代码重新加入”→ 5 秒前再次提醒 → 重建）。新代码会显示在房主的聊天里，用 `/announce` 复制后贴到 Discord 等或抄到引导房。默认关闭（只发引导）。
- 重建会被计为故意断线，请不要连续使用（[3.4](#34-关于封禁与踢出)）。

### 25.4 便利房的注意事项

- 完全不发送职业、名字标签和私密消息。欢迎语和提示合并为一条广播，包括 `/cmd …` 在内的所有命令都对所有人可见（欢迎语第二行会说明这一点）。
- 屏幕左上角显示黄色的 `(unregistered)`，发送间隔 0.3 秒，数据包更小。
- 房主死亡期间的广播，按原版规则只有死者能看到。请勿与游戏主持模式同时使用。
- 即使在便利房里，服务器也仍有可能把房主的广播视为作弊而断开房主（v0.4.0 的未解决事项；断开后 `/rehost on` 的自动重建可用）。遇到时请发送 [报告 zip](#28-如何报告问题)。
- 镜像 Skeld（Dleks）改用与 AUR 相同的方式（设置里的地图始终是 The Skeld，仅在房主端替换飞船实体），因此在已注册和未注册的房间都能提供（v0.4.2）。未注册房间仍存在上面所说的“有人加入时房主被断开”的已知问题（与 Dleks 无关）；在已注册的职业房中可正常游玩。
- 注册关闭会保存到配置文件，重启游戏后**仍保持关闭**。要恢复职业，请输入 `/opt register on` 后重建房间。

## 27. 已知限制与注意事项

**显示相关**

- 警长、豺狼、纵火犯和崇拜者的开场动画显示为“内鬼”（队友只有自己）（[第 26 章](#26-原版玩家看到的是什么)）。在警长、豺狼、纵火犯、崇拜者眼中 **其他所有人都是船员**。有多个豺狼时也无法互相识别（豺狼之友也只能靠名字标签的颜色分辨：豺狼之友始终看到豺狼是蓝色，豺狼只有在 `KnownToJackal` 开启时才看到豺狼之友是蓝色）。真正的职业会在开场动画之后立刻通过名字标签和聊天送达（提前告诉玩家“开场动画不一定准”会更友好）。
- 原版客户端的结束画面只有“Victory / Defeat”。哪个阵营获胜、谁是什么职业，请在房主的画面（结束画面的获胜者显示）和回到房间后的聊天（`/cmd l`）中确认。
- 模组消息以房主角色的聊天气泡送达，发送者名字为“PocketRoles”。每条不超过 100 个字符，数字为全角，每条只有一种颜色。
- 房主死亡期间发送模组消息时，通信上房主会短暂被视为“存活”（关闭注册的房间不执行此处理，因此死亡房主的消息只有死者能看到）。
- 放逐后的几秒内，为了防止黑屏，部分玩家的显示（职业、生死）可能暂时与实际不同。
- 拥有特殊职业的玩家和游戏主持模式下的房主死后不会成为守护天使（成为普通幽灵）。
- 设置标签页、齿轮面板的标题和项目名按房间默认语言显示（可通过 `lang\*.json` 中的 `opt.section.*` / `opt.name.*` / `ui.gear.*` 更改）。
- 房间剩余时间是 **估算值**（收到服务器通知之前从 597 秒倒数）。可能有几秒到十几秒的误差。
- 外观自定义只影响房主的屏幕。皮肤、宠物无法替换。
- 名字标签的符号 ♥（恋人）†（女巫）♨（纵火犯）Ⓦ（崇拜者）可能因客户端字体而显示为 □（可通过源代码中的常量 `Lovers.Heart` / `Witch.Mark` / `Arsonist.Mark` / `Worshipper.ImpostorViewMark` 更改）。

**命令与聊天**

- 不加 `/cmd` 输入的命令（如 `/n`）会作为普通聊天让所有人看到。关闭注册的房间（便利房）中 `/cmd …` 也是所有人可见，而且不分配职业（[第 25 章](#25-便利房关闭注册与引导房)）。
- 主机、Switch、手机上只能使用快捷聊天的玩家 **可以阅读** 职业通知和命令回复，**但不能输入命令**（也无法使用 `/lang`，这类参与者较多时请把房间默认语言调整到合适的语言）。刺客的猜测也是聊天命令，所以这类玩家成为刺客时无法猜测（可以正常击杀）。
- `[Chat] PlayerCommands`（或 `AllCommands`）关闭的房间不会分配刺客（即使人数设为 1 以上也会跳过，房主会收到提示）。不加 `/cmd` 的 `/guess` 会被所有人看到（回复中会附带提醒）。
- 玩家的 `/lang` 选择保留到房主关闭游戏为止（按好友代码 / Puid）。
- 游戏主持模式下房主输入的普通聊天，按原版规则存活者看不到。
- 聊天翻译是机器翻译。短句、梗、专有名词可能翻译错误。Google 的公开接口是无密钥的尽力而为，拥挤或短时间内发送过多时会失败（每分钟最多 `MaxPerMinute` 次）。翻译会延迟几秒送达。
- 翻译开启期间（默认开启），聊天文本会从房主的电脑发送到 Google / DeepL（[第 13 章](#13-语言日本語--中文--english)）。为了告知玩家，欢迎语中会有提示。
- 语言自动识别依赖翻译服务的判断，混合语言或很短的句子可能不会切换（本人可以用 `/cmd lang …` 选择）。
- 权限（管理员 / 版主 / VIP / 封禁）通过好友代码 / Puid 识别，本地（局域网）房间中无法使用。即使是管理员，`/mod on|off`、`/test`、`/assign`、`/end`、`/haison`、`/endmeeting` 等仍仅限房主。VIP 的 ★ 所有人都能看到（仅游戏中的名字标签）。

**游戏进程**

- **不支持房主迁移**。房主退出后职业信息会丢失，该局无法正常继续（房主的电脑请留到对局结束）。在别人的房间中接任房主时，由于该房间未注册，模组保持停用（聊天中会有提示）。
- 职业只从“普通船员”“普通内鬼”名额中分配。成为原版特殊职业（科学家、工程师、变形者等）的玩家不会获得特殊职业。吸血鬼、黑手党、女巫、刺客、邪恶鹰眼、邪恶猫又、连环杀手、武士占用内鬼名额，所以内鬼设为 1 人、吸血鬼设为 1 时，那 1 人就是吸血鬼（`/assign` 不受此限制）。豺狼之友只有本局分配了豺狼时才会分配。恋人的第一人从船员名额中选出，第二人从船员名额（`AllowImpostor` 开启时也包括内鬼名额）中选出，每局最多一对。
- 恋人的胜利判定排在小丑、恐怖分子的单独获胜之后（小丑被投出的对局即使恋人都存活也是小丑获胜）。内鬼恋人在内鬼获胜的人数判定中算作内鬼，但只能作为恋人获胜。
- 警长、豺狼、纵火犯、女巫（设置了诅咒冷却时）、点灯人、增速者、鹰眼狂粉、崇拜者、连环杀手、武士（设置了斩击冷却时）、邪恶鹰眼的效果是作为该玩家专属的“游戏设置”发送的，所以在房间设置变更等导致原版设置重新发送后，可能暂时恢复为普通值（游戏开始时、开场动画结束时、会议后会重新发送。连环杀手在开场动画后和会议后会直接重设击杀键，因此不受影响）。
- 疯狂特技演员只能挡下用击杀键进行的击杀（包括作为咬人、诅咒、斩击的直接目标）。投票放逐、刺客的猜测、断线无法阻止。警长、豺狼只会收到“挡下了”，但射击后不死的只有疯狂特技演员，所以职业可以被推断出来。房间击杀冷却不足 1 秒时，挡下后击杀者的冷却也是 1 秒（到下次会议为止）。
- 武士斩击的范围按房主端的位置判定（玩家的位置会因网络延迟晚几百毫秒，所以边界附近的人可能被斩到也可能没有）。被波及者以 0.3 秒间隔依次死亡，因此胜负判定和诱饵的自动报告会等到最后一人倒下（最多“间隔 × 人数 + 1 秒”）。在此期间进入管道、梯子或断线的人可能活到游戏结束。斩击冷却为 0（= 房间的击杀冷却）且房间冷却也是 0 秒时，会议刚结束就能斩击，建议设为 2.5 秒以上。
- 崇拜者的崇拜会让对方当场变成内鬼狂粉，因此崇拜的瞬间游戏可能立即结束：内鬼获胜（人数判定）或船员获胜（对方持有最后的未完成任务时）。对无法崇拜的对象（狂粉系职业、警长、豺狼、纵火犯、船员方的恋人）按下按钮时，崇拜者会看到击杀失败的效果并收到“无法被崇拜”的聊天，因此能知道对方是这些职业之一（设计如此）。
- 房主自己是邪恶猫又并被投出时，为了发送放逐画面约 2 秒后的全员提示（`Announce` 开启时），通信上房主会短暂（约 1 秒）被视为“存活”（玩家的画面上可能短暂看到被放逐的房主是活着的。仅为显示问题）。
- 测试模式下胜负判定暂停。正式开房前务必 `/test off`（重建房间会自动关闭）。
- 自动重建、`/move`、延迟过高的重建产生的房间 **房间代码会改变**（废村则不会改变）。请重新告诉玩家（用引导房的话也改一下它的名字）。
- 短时间内反复重建房间、对局中途退出，会累加官方服务器的 **ban points**，暂时无法创建房间（[3.4](#34-关于封禁与踢出)）。
- 废村的一次性对局也有开场动画，会有人被显示为原版职业（内鬼）。不分配职业，并立即结束。
- 可延长的次数和时机取决于服务器。没有收到延长询问时会执行废村。
- 房间剩余时间的显示、自动开始、延长、废村、`/time` 只在在线房间中工作。
- 会议剩余时间的显示由各客户端自己保存，房主无法缩短（只能截止）。
- 自动选择区域会覆盖游戏的区域设置。想手动固定区域时请关闭。
- 原版设置范围扩展中使用极端值（投票 0 秒、击杀冷却 0 秒、30 个任务、速度 5 倍等）时，可能出现原版没有考虑到的行为（会议瞬间结束、任务列表过长等）。放宽的只是设置界面的行和 `/vset`，不会改变预设的值。
- 仅支持经典模式。躲猫猫 / Seek Fools 模式下模组停用。

**服务器与反作弊**

- 官方服务器有通信量限制，超出时房主会被判定为“hacking”踢出。模组已把发送分散，但人数越多（15 人）风险越高。
- 已注册的房间不会出现在公开列表中（第 3 章）。开启自动公开也一样。关闭注册的便利房会出现在列表里但没有职业，而且房主的广播仍有可能导致断开（第 25 章）。
- 作为房主端的简易反作弊，如果收到了只有房主才能发送的 RPC（职业变更、名字变更、击杀、放逐等）来自玩家，会忽略并记录日志，并在房主画面上提示。`KickOnForgedRpc = true` 时 3 次后踢出。
- 游戏版本与支持版本不同时模组自动停用（第 24 章）。

## 29. 构建方法

需要：**.NET 8 SDK**。`build.cmd`（和启动器）在存在 `%USERPROFILE%\.dotnet\dotnet.exe`（用户级安装）时使用它，否则使用 PATH 中的 `dotnet`。

```
build.cmd
```

（内容是 `dotnet build -c Release`。启动器的“仅重新构建”也相同。）输出为 `bin\PocketRoles.dll`，如果 `..\Among Us PocketRoles\BepInEx\plugins` 存在则自动复制过去。

- 引用的 DLL 位于 `..\Among Us PocketRoles\BepInEx\core` 和 `BepInEx\interop`（interop 在第 5 章的首次启动时生成。请先运行一次游戏）。
- 引用其他文件夹中的游戏：`build.cmd -p:GameDir="C:\path\to\Among Us"`
- 目标：net6.0，C# latest，Nullable off，ImplicitUsings off。不使用 NuGet 的游戏库或 Reactor。
- `lang\*.json` 和 `assets\PocketRoles-256.png`（标题画面的图标）作为嵌入资源包含在 DLL 中，语言文件在首次启动时写出到 `BepInEx\PocketRoles\lang\`。想修改文本时不必重新构建 DLL，编辑写出的文件即可。
- 运行确认：启动模组副本中的 `Among Us.exe`，确认 `BepInEx\LogOutput.log` 中有 `PocketRoles v0.5.0 loaded` 且没有 Harmony 补丁错误。

生成发布 zip：`powershell -NoProfile -ExecutionPolicy Bypass -File build-release.ps1`（`-SkipBuild` 跳过构建）。会生成 `dist\PocketRoles-<ver>.zip`（`BepInEx\plugins\PocketRoles.dll`、`BepInEx\PocketRoles\lang\*.json`、3 种 README、LICENSE、NOTICE）、`dist\PocketRoles-Setup-<ver>.zip`（`PocketRolesLauncher.ps1`、`PocketRoles Launcher.cmd`、`assets\PocketRoles.ico`、`はじめに.txt`）和 `SHA256SUMS.txt`。版本取自 `PocketRoles.csproj` 的 `<Version>`。把这两个 zip 附加到 GitHub Releases 后，启动器的“检查更新”“安装”就能获取最新版本（会查找名为 `PocketRoles-<ver>.zip` 的资源）。

源代码结构（`src\`）：

| 文件夹 | 内容 |
|---|---|
| `PocketRolesPlugin.cs` | 插件本体、版本检查、左上角显示、每帧处理 |
| `Core\` | 职业定义（Roles）、语言（Lang）、设置及设置标签页的项目列表（Options）、对局状态（GameState）、延迟执行（Scheduler）、快捷键（Hotkeys）、权限（Permissions：Admin / Moderator / VIP / Banlist.txt、踢出与封禁） |
| `Net\` | 按客户端发送与安全模式（Rpc）、单独游戏设置（OptionsDesync）、+25 注册（Registration）、简易反作弊（AntiCheat） |
| `Game\` | 职业分配（RoleAssignment）、诊断（Diagnostics：`/diag`）、名字标签（NameTags）、击杀 / 跳管 / 破坏（Kills）、会议（Meetings）、强制结束会议（MeetingTools）、黑屏对策（AntiBlackout）、胜负（WinConditions）、测试模式（TestMode）、游戏主持（GameMaster）、原版设置范围扩展（VanillaRanges：设置界面的行与 `/vset`） |
| `Chat\` | 聊天发送、欢迎语与规则行（Chat）、命令（Commands）、聊天翻译（Translator：Google / DeepL、语言自动识别） |
| `Lobby\` | 自动重建房间 / 自动公开 / `/move` 的重建（Rehost）、延迟过高的询问对话框（RehostPrompt）、房间计时（LobbyTimer）、自动开始 / 废村 / 取消按钮（AutoStart）、废村后返回房间（HaisonReturn）、自动选择区域（AutoRegion）、镜像 Skeld（DleksMap） |
